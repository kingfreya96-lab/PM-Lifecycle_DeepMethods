# 流程的边界 — 这套工作流不承诺什么

**问题**：用户原始流程的最后一句写得很准——"结果可以支持或反驳判断，
但不能保证未来必然成功"。但这句话在整个 skill 里**没有承载位置**。
记录卡只有"结论"和"未决假设"，没有地方写"**这次判断不承诺什么**"。

结果是一种隐蔽的过度自信：卡片写完了、证据分级做了、门控过了，
读的人（包括三个月后的自己）会以为**结论已经被证明了**。
实际上 E1 行为数据只证明了"过去某个时段发生过什么"，
它不证明"未来会继续这样"，更不证明"我们会做对"。

本文件是这套流程的**认识论边界声明**。它不是免责声明，是**每张记录卡都要填的一栏**。

---

## 1. 记录卡新增一栏：本次判断不承诺什么

每张记录卡在「结论」段之后必须加：

```
### 本次判断不承诺什么

**本卡支持的结论**（有证据支撑的范围）：
**本卡不支持、也不能被引用为依据的**：
- 未来该结论仍然成立
- 换个人/换团队执行也会得到同样结果
- 产品会成功、用户会付费、留存会好
**如果哪条推论被依赖过，那它超出了本卡的证据范围**：
```

第三行是关键：**假设后面有一个"推论依赖检查"**。
如果有人在别的文档里引用了"这个方向验证过了"，
但那个结论其实依赖的是本卡**不覆盖**的部分，那就要在这里点名。

---

## 2. 四类推论，各自有边界

这是本文件的核心内容。不同类型的结论，能被推多远是不一样的。

| 结论类型 | 例子 | 能支持 | **不能**支持 |
|---|---|---|---|
| **存在性** | "确实有用户遇到这个问题" | 说明问题不是我们臆想的 | 不能推"问题普遍"、不能推"问题重要" |
| **频次/规模** | "X% 的用户每月遇到 3 次以上" | 说明值得投入 | 不能推"我们能解决它"、不能推"值得付费" |
| **因果性** | "做了 A 之后 B 上升了" | 说明干预有效 | 不能推"换个场景也有效"、不能推"长期仍然有效" |
| **可行性** | "我们能做出这个" | 说明做得出 | 不能推"做出来用户会用"、不能推"做出来会赚钱" |

**最常见的越界**：用**存在性**证据去支撑**重要性**结论，
用**可行性**结论去支撑**商业性**结论。
`thinking-scaffold.md` §2 的假设分层（L1 价值 / L2 使用 / L3 可行 /
L4 商业 / L5 合规）就是这条边界的规范化表达——**层次不能互串**。

**记录卡落点**：「本次判断不承诺什么」的"不支持"栏要写出**具体推论**，
不是写"不能保证成功"这种谁都能写的空话。

---

## 3. 有些判断确实不可证伪

`thinking-scaffold.md` 要求"品味判断必须可测化"。但这有一条**边界**：

**不是所有判断都能测化。** 有些判断是关于：
- 长期品味的形成（"这个产品的调性对不对"）
- 团队能力与文化的匹配
- 时机（"这个窗口期对不对"）
- 组织政治（"这个方案能不能推动下去"）

**强逼这些判断"可测化"会产出假指标**——造一个测不出真东西的指标，
然后宣称自己"可证伪了"。这比诚实地承认"这条是品味判断"更坏。

**规则**：
- 记录卡允许一条判断标记为 **「品味判断（暂不可测）」**。
- 标记后必须写：**什么时候能变成可测的**，或**什么情况下这条判断被证明为错**
  （"如果 3 个月后团队还是用同样的方式争论，说明判断错了"也算）。
- 标记为品味判断的，**不能承载门控**（与 E5/E6 同级处理：可记录，不支撑）。
- 但它**可以**写进「反面证据」——"我担心这个调性不对"是真实的反面信号。

> 这条是对 §5c 原则的延伸：**脚本不能逼作者写假东西。**
> 逼一个品味判断伪装成指标，比让它诚实地标出来更糟。

## 4. 决策者本人的位置

`thinking-scaffold.md` §3 的反方协议是"**谁会反对**"——
一个外部角色，用他们的语言。缺了一维：**决策者自己可能错了**。

不是"我可能犯错"这种正确但无用的话，而是**具体的三个提问**：

| 提问 | 问什么 | 不合格的答案 |
|---|---|---|
| **我的框架** | 我用什么分类/指标在看这件事？这个框架漏掉了什么？ | "应该挺全面的" |
| **我的位置** | 我在这个决策里有利益吗？我会因为什么而希望它是 GO？ | "我没有私心" |
| **我的锚** | 我是不是被第一个数字/第一个竞品/会议室里的第一个人锚定了？ | "没有刻意引导" |

**这三问写进记录卡**（或写进 `lessons.md`）。目的是**暴露自己的盲区**，
不是表演谦逊。写"我没有私心"等于没写。

**对 AI agent 尤其重要**：agent 做判断时没有"利益"，但有强烈的
**"把任务完成"的倾向**——倾向于把模糊的东西写成确定的、
倾向于让校验通过、倾向于满足格式要求。所以 agent 的自问要额外加一条：

> **我是不是在把"格式正确"当成"判断正确"？**
> 这张卡每一栏都填了，但每一栏的**依据**是不是真的存在？

## 5. 敷衍式填卡怎么识别

这套流程假设执行者认真填卡。现实中会有**敷衍式填卡**——
每栏都填了，但内容是套话。特征：

| 特征 | 例子 |
|---|---|
| 证据内容是常识复述 | "用户希望产品更好用" |
| 来源写的是文档名不是数据 | "来源：用户调研报告" |
| 时间/口径/样本是占位 | "时间：2026 年，口径：全面，样本：多" |
| 反面证据是"暂未发现"且没写搜索范围 | "已主动搜索，暂未发现" |
| 结论是动词+形容词 | "可以推进一下" |

**识别方式（脚本可查的部分）**：
- 「反面证据」写"暂未发现"但**没写搜索范围** → **警告**
- 证据的「样本」栏写"多"/"若干"/"一些" → **警告**
- 证据的「时间」栏不是具体日期或时间窗 → **警告**
- 「来源」栏出现"报告"/"文档"/"资料"且**没有文件路径/URL** → **警告**
- 「结论」段超过 3 句但**没有出现任何 E 编号** → **警告**

> 都是**警告**不是错误：可能作者只是写得简略。
> 但**连续三张卡出现同类警告** → 说明填卡文化已经坏了，该在阶段 19 记一笔。

**无法用脚本识别的**：内容是否真的诚实。只能靠反方协议 + 双人标注 +
`calibration.md` 的命中率来间接发现。**这就是为什么校准回路是必需的**——
它是唯一能发现"系统性说谎"的机制。

## 6. 阶段 1/2 的"什么都不做"

机会成本表在阶段 4/5/6/16 已经强制包含"什么都不做"作为候选。
但**阶段 1（发现问题）和阶段 2（初步筛选）**——也就是"要不要开始研究"——
没有这个锚点。结果是：**信号一出现就开始研究，研究本身变成沉没成本。**

**规则**：
- 阶段 1 的候选问题表，必须包含一条 **「什么都不做」的基线**：
  假设我们不做任何事，这个问题会怎样？用户会怎么应对？代价是什么？
- 阶段 2 的筛选结论，如果**"什么都不做"不是被比较过的候选之一**，
  「继续」就只是默认选项，不是判断。→ 记录卡警告。
