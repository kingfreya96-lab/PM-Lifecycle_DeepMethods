# 方法论沉淀 — 让 skill 越用越准

**问题**：现在这个 skill 是**静态文档**。跑完之后，除了 20 张记录卡，什么都没留下。
下一个项目从头开始，同一个坑踩第二次。

**顶尖的做法**：skill 不是文档，是**带反馈回路的系统**。
每跑一轮，产出三样东西：① 阶段产物 ② 决策与预测记录 ③ **方法论更新**。

本文件定义第 ③ 样。

---

## 1. 三层沉淀结构

```
lessons.md      本轮学到什么（原始素材，追加式）
    ↓ 每 3 轮或阶段 19 归档时提炼
patterns.md     反复出现的模式（升级为默认规则）
    ↓ 反复验证有效
SKILL.md / references/*.md   写进流程本身（最高级沉淀）
```

**关键**：不是每条经验都值得写进 skill。
进 skill 的门槛是：**在 ≥2 个不同项目/场景里被验证有效**。
只出现过一次的，写进 `lessons.md`；两次以上，写进 `patterns.md`；
验证过且能写成检查项的，才改 `references/*.md`。

---

## 2. lessons.md 的格式

追加式，不许删改历史（历史也是证据）。

```markdown
## L-2026-10-24-001 · 阶段 1 · 信号真实性
**当时的情形**：阶段 1 拿到一条老板想法 + 两条二手社区帖子，我差点判 GO。
**我错在哪**：把两条 E2 原话当成了"问题普遍存在"的证据。
**根因**：没有分清"存在性断言"和"频次断言" —— 2 条原话只能证明存在。
**怎么识别（下次的具体判据）**：任何频次/普遍性表述，必须挂 E1；
  记录卡里出现"常见""普遍""大多数"却没有 E1 引用 → 判据命中。
**落到哪个检查项**：`references/evidence-discipline.md` 第 1 节；
  `scripts/gate_check.py` 新增检查：结论段含普遍性词但无 E1 → 警告。
**生效日期**：2026-10-24
**验证状态**：待验证（需要在下一个项目复现一次）
```

**「怎么识别」这一栏是核心**。只写"我下次注意"等于没沉淀 ——
下次注意需要意志力，判据不需要。

## 3. patterns.md 的格式

同一类问题出现 ≥2 次，升级为 pattern。

```markdown
## P-003 · 小样本冒充普遍性
**出现场景**：阶段 1/3/9 反复出现（3 次）
**典型形态**：用 5-8 个访谈推出"大部分用户会……"
**已升级为**：references/evidence-discipline.md 第 1 节的样本量纪律表
**适用阶段**：1, 3, 7, 8, 9, 14, 15
**验证状态**：已生效（下次复现后标"已验证"）
```

## 4. 什么时候提炼（不要随时）

**三个提炼点**，不要随时改 skill：

1. **阶段 12 开发落地结束** — 开发期最容易暴露"文档假设与现实不符"。
2. **阶段 17 上线监测** — 真实用户反馈会打脸多个判断。
3. **阶段 19 归档** — 全程回顾，此时才有完整信息。

**提炼动作**：
1. 读本轮所有 `lessons.md` 条目。
2. 合并同类项，标出**重复出现 ≥2 次**的 → 进 `patterns.md`。
3. 回头对照 `references/decision-contract.md` 的四态裁决 + `evidence-discipline.md`，
   看哪些教训**能变成一条检查项**（机器可判的）→ 改 `scripts/gate_check.py`。
4. 每条改动的检查项都要有**回归测试**（`scripts/test_gate_check.sh` 加一条）。

> **这是 skill 唯一应该变的地方**：能变成检查项的，进脚本；
> 只能靠人判断的，进 references；都不行的，进 lessons.md 备查。

## 5. 什么不值得沉淀

防止 skill 被噪音淹没。以下**不进**沉淀：

- 一次性环境问题（网络、工具故障）→ 记在当轮记录卡，不进 lessons
- 没有下次可操作性的一般性感想（"要多沟通"）→ 跳过
- 别人明确说"这次是特例"的事 → 跳过
- 只在当前产品成立的业务知识 → 属于产品文档，不属于 skill

**判据**：这条经验能改变**下次**的具体动作吗？不能 → 不沉淀。

---

## 6. 沉淀的验收标准

阶段 19 归档时，沉淀是否合格，用这四条自查：

| # | 检查 | 不合格的样子 |
|---|---|---|
| 1 | 每条 lesson 都有"怎么识别"栏 | 写"下次注意" |
| 2 | 每条 lesson 指向了一个具体检查项或文档位置 | 只写感想 |
| 3 | 每条升级进 skill 的检查项都有回归测试 | 改了脚本没加测试 |
| 4 | patterns 里的每条都注明了出现次数与验证状态 | 没统计来源 |

**四条有一条不满足 → 沉淀没做完**，阶段 19 的门控不能是 GO。

## 7. 本 skill 自身的沉淀记录

以下是 skill 维护过程中沉淀的**流程级**教训（区别于用户在项目里记的 lessons）。

| 编号 | 场景 | 教训 | 落在哪 |
|---|---|---|---|
| S-001 | 校验脚本把 E6 证据行判失败 | **校验器不能逼作者造假**。真实发生过的事必须能记录；判据要分「报错=不可用」与「警告=有话要说」两档 | `decision-contract.md` §5c + `gate_check.py` |
| S-002 | 文档说「三个 PM 库」但实际四个；文档说「已写死绝对路径」但已改占位符 | **文档与实现不符会误导使用者**。每次改实现要回查描述性句子 | 发布前路径自检 + 双侧一致性校验 |
| S-003 | 发布副本残留本机专属路径 | **发布物必须对陌生人可用**。本机路径静默失效 = 别人以为 skill 坏了 | `sync_install.py --publish` 的路径自检闸 |
| S-004 | 发布说明里举例写到了被禁字符串 | 自检要区分「举例说明」和「真实引用」——描述被检查的字符串本身也会命中 | 文档举例改用类别词（"本地 bundle 目录名"） |
| S-005 | 阶段 8/9 的产物清单里没有评估集 | **规范写了不等于流程接上了**。检查点必须在该阶段的产物清单里出现 | `references/stages/stage-08.md`（阶段 8）+ `workspace.py init` |
| S-006 | 裁决记了预测但没人对账 | **写下来不等于形成回路**。预测必须有打分入口 | `workspace.py score` + 阶段 15/17/19 引用 |
| S-007 | 单条预测读出 "+60pp 偏差" | 小样本统计必须报噪声警告，否则噪声会被当信号 | `calibrate.py` 区间样本量门槛 |
| S-008 | 红线校验的错误信息让作者写「不适用」，代码却只认 `RL-1` 行 | **错误信息承诺的写法必须被代码接受**，否则作者诚实地照做反而失败 | `gate_check.py` 红线区块支持「不适用 + 理由」 |
| S-009 | 「授权人=老板」通过校验 | **头衔不是人名**。「老板/领导/上面」说明了权力但没说明谁做的 | `gate_check.py` 占位词表加入头衔类词 |
| S-010 | 模板的括号提示被当成作者填的内容 | 模板占位符必须能被识别为"未填"——否则可选区块会让空模板必然失败 | `_is_placeholder()` 统一判据 + `_field_value` 剥离括号提示 |
| S-011 | 阶段 1/2 没有「什么都不做」的锚点 | 机会成本表在阶段 4/5/6/16 强制含「什么都不做」，但早期阶段没有 → 信号一出现就开始研究 | `limits-of-judgment.md` §6 |
| S-012 | 流程假设执行者会认真填卡 | 敷衍式填卡要有可查的特征（样本写量词、时间无日期、来源只写材料类型、反面证据无搜索范围） | `limits-of-judgment.md` §5 + `gate_check.py` |
| S-013 | 模板占位符 `<...>` 被 `_clean` 吃掉了闭合括号 | **占位符识别必须容忍全角/半角角括号**，且 `_clean` 不能把 `>` 当引用符剥掉 | `PLACEHOLDER_RE` + `_clean` 只剥 `"> "` |
| S-014 | 「门控例外」区块在记录卡末尾时字段被判缺失 | **可选区块的位置不能假设在固定位置**；取块内字段只应在下一个标题处停 | `_check_gate_exception` 的 stop_labels 改为只认标题 |
| S-015 | 测试的 `fill()` 把门控例外的 `<YYYY-MM-DD>` 一并替换成真实日期 | **夹具的批量替换会误伤其它区块**；填一个区块前先确认不会碰到相邻区块的占位符 | `test_gate_check.sh` 的 `fill()` 显式还原例外区块 |

**加新检查项的规矩**：先在 `assets/ai-lanes.json`（AI 字段）或 `references/*.md`（规则）里
定义**单一真源**，再让 `gate_check.py` / `workspace.py` 读它，
最后在 `scripts/test_gate_check.sh` 里加回归用例。
**三处各写一份 = 迟早分叉。**

**另一条规矩（2026-10-24 决策官视角新增）**：
新增任何检查时，先问一句"**作者能不能诚实地填这一栏而不被判失败**"。
如果答案是否定的，这个检查要么设计错了，要么该降级成警告。
S-008 到 S-010、S-013 到 S-015 都是这条规矩被违反后才发现的。
