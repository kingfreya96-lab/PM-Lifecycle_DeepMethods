# 品味（Taste）— 让"好产品"可判定

**问题**：现有 skill 能判断"证据够不够、门控过不过"，但判不了"这东西好不好"。
结果就是：流程跑得很认真，产出的东西却平庸。

**顶尖的人怎么解决**：不靠天赋，靠**对照 + 反模式 + 事前定标准**。

---

## 1. 品味的三条工作原则

### 原则一：品味是对照出来的，不是想出来的

单看一个方案好不好，说不出来。**并排放三个做过的和三个别人做的**，立刻能说出差在哪。

所以每个阶段产出方案时，必须回答：
> 这个东西比我见过的哪三个东西好/差？差在哪个具体维度？

维度必须具体，不能是"体验更好"：
- 首次使用到第一次成功的**步数**
- 关键任务的**完成率**
- 决策点**是否可撤销**
- 默认值是否安全
- 失败时的**下一步是否明确**

### 原则二：先写反模式，再写方案

顶尖团队会维护一份**反模式清单**——明确说"我们不做这样的东西"。
这比"我们要做什么"更能守住品味，因为方案会被各种理由改，反模式是底线。

本 skill 的默认反模式库（每个产品可以增补）：

| # | 反模式 | 症状 | 为什么差 |
|---|---|---|---|
| A1 | 功能堆砌 | 一个需求里塞 5 个功能 | 用户要的是解决一个具体问题，不是能力清单 |
| A2 | 空状态即默认 | 空状态写"暂无数据" | 空状态是最重要的界面，却常被当占位符 |
| A3 | 不可逆决策 | 关键操作没有二次确认 | 不可撤销的错误必须先问 |
| A4 | 假智能 | 用"AI 智能推荐"包装规则排序 | 承诺了智能却给不出惊喜，信任一次性透支 |
| A5 | 打扰式引导 | 首次进入就弹三个引导 | 引导本身是流失点，不是帮助 |
| A6 | 数字无意义 | 显示"已优化 37%"但无基准 | 无基准的数字是噪音，会训练用户忽略数字 |
| A7 | 兜底即失败 | 出错只给"出错了" | 失败状态必须给出下一步动作 |
| A8 | 沉默的等待 | 加载超过 1 秒无反馈 | 用户无法判断是卡了还是没点到 |
| A9 | 权限过度 | 一开始要全部权限 | 权限请求是转化断崖，也是信任门槛 |
| A10 | 移动端降级 | 桌面能用、手机全废 | 真实使用场景常在手机上 |

**用规则**：任何阶段产出方案时，要逐条对照反模式库，命中就写进记录卡的「反面证据」。

### 原则三：标准要在动手前定

**事前定标准，事后凑答案 = 自欺。**
所以"什么算好"必须在做之前写成可测的量：

| 阶段 | 事前定标准的动作 |
|---|---|
| 3 验证问题 | 写出"多大代价的问题才值得做"的数值门槛 |
| 7 衡量标准 | 指标 + 基线 + 阈值 + CI 下界 |
| 8 验证计划 | 成功/失败/**证据不足**三个阈值 |
| 9 方案比较 | 统一维度表 + 每个维度的达标线 |
| 14 试点 | 预注册阈值 + 停止条件 |
| 16 发布 | 放量分步 + 每步判据 + 回滚条件 |

这已经在 skill 里，但**"事前"两个字是全部意义所在**。事后再定标准 = 一定被结果牵着走。

## 2. 品味不是形容词：坏品味的具体形态

区分"我觉得不好"和"这是坏品味"：

| 坏品味 | 好品味 |
|---|---|
| "感觉不够高级" | "首屏三个同权重的卡片，用户没有决策依据" |
| "这个界面很乱" | "主操作和次操作视觉权重相同，CTA 不明确" |
| "文案不高级" | "文案说'欢迎使用我们的智能助手'，而用户刚进来只想知道怎么开始" |
| "功能不够" | "缺少空状态与失败态的处理" |
| "不够极简" | "删掉了一个低频但有价值的设置项，代价是每层多一次点击" |

**规则：任何一条"我觉得"，要翻译成"具体哪个维度、差多少、参照什么"。**
翻译不出来，说明它不是判断，是情绪。

## 3. 每个阶段的"品味检查点"

不是每阶段都要审美判断，但每阶段都有对应的品味维度：

| 阶段 | 品味检查点 | 判据 |
|---|---|---|
| 1 发现问题 | 问题陈述的颗粒度 | 能不能直接推出 3 个不同解法？只能推出 1 个 = 颗粒度太粗 |
| 2 初筛 | 是不是在找证据支持已有结论 | 抽样时是否专门去找反对者 |
| 3 验证问题 | 问题陈述有无功能污染 | 出现功能名/按钮名 = 回退 |
| 4 市场机会 | 估算是否自下而上 | 有没有真实的单价×数量来源，还是拍的 |
| 5 方向选择 | 舍掉了什么 | 有没有写下"本次明确不做什么" |
| 6 产品方向 | 边界是否可执行 | "不做"清单是否都是具体可判的 |
| 7 衡量标准 | 指标能否被一个看板复现 | 每个指标有没有分子/分母/口径/时间窗 |
| 8 验证计划 | 有没有"证据不足"分支 | 三态阈值齐不齐 |
| 9 方案 | 反模式对照 + 统一维度比较 | 落选方案的落选理由是否写下来了 |
| 10 可行性 | MVD 是否还能量到核心假设 | 砍完还测得到吗 |
| 11 PRD | 验收条件是否可测 | 有没有"友好/高效/稳定" |
| 12 开发 | 新证据是否及时回流 | 24 小时内记录了吗 |
| 13 上线准备 | 回滚演练过没有 | 有没有计时记录 |
| 14 试点 | 阈值是不是事前写的 | 有没有事后修改记录 |
| 15 结果分析 | 三态裁决 | 有没有把"没失败"当成功 |
| 16 发布 | 每步能否独立回滚 | 放量计划逐条查 |
| 17 监测 | 趋势而非仅当前值 | 有没有"距离红线多远、在往哪变" |
| 18 规模化 | 规模不经济拐点 | 成本模型有没有标出拐点 |
| 19 退场 | 用户保护四件套 | 通知/迁移/缓冲期/支持齐了吗 |
| 20 AI 审计 | 失败模式枚举 | 是不是只测了平均分 |

## 4. 品味怎么练

品味不会自动变好。有三个可执行的练法：

**练法一：反向拆解（每周 1 个）**
找一个自己觉得"做得好"的东西，写出它好在哪**三个具体维度**。
写不出来 = 你只是觉得它好，还没理解它。理解不了就学不了。

**练法二：对照批评（每阶段一次）**
每次出方案，选一个成熟产品做对照，逐维度列：
`我的方案 vs 参照物 → 在每个维度上谁好、差在哪、为什么`
**参照物必须是已经上线、真实被用过的**，不能是设计稿。

**练法三：证伪自己的偏好（每阶段一次）**
写下一个"我认为对"的设计判断，然后写：**什么证据会证明它错？**
如果写不出来 → 这不是判断，是偏好。偏好不写进记录卡，避免污染后续决策。

## 5. 品味判断如何进预测日志

品味判断也要可校准，写法见 `calibration.md` 第 6 节。

**关键**：品味的 falsifier 必须是可测的。
- ❌ "用户更喜欢 A"（主观）
- ✅ "5 人任务测试中 A 的完成率低于 B"（可证伪）
- ✅ "盲评中 A 未进入前 2"（可证伪）

**当同一个品味判断被证伪 2 次**，它就不再是判断，是偏好 —— 写进反模式库。
这是品味从直觉变成资产的过程。
