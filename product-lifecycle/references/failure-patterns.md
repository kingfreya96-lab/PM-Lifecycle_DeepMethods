# 常见失败模式

> 从 SKILL.md §9 移出。遇到卡住的阶段时按需加载。


## 9. 常见失败模式

| 失败模式 | 表现 | 纠正 |
|---|---|---|
| 阶段 1 变成方案讨论会 | 记录里全是功能名 | 拉回问题层，删掉方案名重写问题陈述 |
| 阈值后补 | 试点结束后才定"什么算成功" | 阶段 7/8 就写死，试点章程预注册 |
| 把"没有失败"当成功 | 裁决写 GO，理由是"没出问题" | 改判 REVISE（证据不足），补试点 |
| 记录卡缺失 | 有结论查不到依据 | 补齐 L3，脚本可查 |
| 范围只增不减 | 开发中发现新需求就加 | MVD 之外的需求走变更记录 + 阶段 6 重评 |
| 红线写成口号 | "注意安全""关注反馈" | 补齐触发条件/监测/负责人/动作四项 |
| **只比较一个候选** | 阶段 5 直接定了方向 | 补齐 ≥2 个候选（含"什么都不做"），或改判 REVISE |
| **拿小样本冒充普遍性** | "大部分用户会……" | 频次断言必须挂 E1；n<30 不报 p 值 |
| **没做过选择就说"用户喜欢"** | 品味判断无参照物 | 补对照物（已上线产品）+ 可测 falsifier |
| **AI 产品没有回归门禁就上线** | 质量悄悄劣化 | 阶段 13 必须有黄金集 + 基线版本 + 阻断规则 |
| **合规项"待确认"就发布** | 阶段 16 GO 带待确认 | 降为 CONDITIONAL，写闭合期限与责任人 |
| **AI 专项留空就过门控** | 阶段 5–19 的「AI 能力工作」表整列空着 | 逐项作答；确实不适用写「不适用 + 理由」；GO 时缺项 = 不通过 |
| **AI 能力最后才想起来做** | 阶段 20 才发现任务根本不适合 AI | AI 适用性在阶段 5 就判定，AI 专项按阶段做，不是最后补审 |
| **门控被绕过且无痕** | 记录卡缺失，但分不清是跳过了还是忘了 | 用「门控例外」区块登记：授权人（具名）+ 被跳过的证据要求 + 风险接受人 + 补救期限 + 补救责任人。**没有合法绕过通道 = 逼人偷偷不记录**（`references/decision-rights.md` §2）|
| **结论被当成已证明** | 后续文档直接引用「这个方向验证过了」 | 每张卡填「本次判断不承诺什么」，把超出证据范围的推论点名（`references/limits-of-judgment.md` §1）|
| **难逆决策当可逆决策拍板** | 发布类门控只走过场 | 标可逆性 R1–R4；R3/R4 必须有具名复核人（`references/decision-rights.md` §1）|
| **门控开三天会** | 流程变成服从的仪式 | 记录「门控成本」，对照阶段时间盒；秒过也要写——那是没做判断 |
