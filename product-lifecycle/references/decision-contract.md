# 共享决策契约 — 20 阶段通用的证据、门控与记录格式

本文件是全流程的**判定基础设施**。每个阶段的 `references/stages/stage-NN.md` 只写该阶段特有内容，
证据分级、门控语义、记录格式统一在这里定义，避免 20 份文档各说各话。

## 1. 三层判定结构

每个阶段都必须走完这三层，顺序不可颠倒：

| 层 | 时长 | 作用 | 失败时的动作 |
|---|---|---|---|
| **L1 快速判断** | ≤ 60 秒 | 判断"这个阶段现在该不该做、该做到什么程度" | 直接裁决，跳过深度工作 |
| **L2 门控** | 一次会议/一次书面评审 | 按预定阈值裁决 继续 / 有条件继续 / 返工 / 终止 | 裁决落档，进入下一步或退出 |
| **L3 记录** | 5 分钟 | 写阶段记录卡，保证结论可追溯 | 记录不全 = 门控未通过 |

**为什么分三层**：绝大多数 PM 流程失败不是因为判断错，而是因为**跳过了 L1 直接开会**，或者
**过了 L2 却没留 L3 记录**，导致三个月后没人知道当初为什么做这个决定。

## 2. 证据分级 E1–E6

所有阶段的"优先证据"字段都必须使用这套等级。裁决时只认等级，不认语气。

| 等级 | 含义 | 例子 | 能单独支撑的裁决 |
|---|---|---|---|
| **E1** | 真实用户行为数据 | 埋点、转化漏斗、留存 cohort、真实交易 | 可授权投入与发布 |
| **E2** | 真实用户原话 | 访谈逐字稿、工单原文、公开评论 | 可授权深入研究；配合 E1 可授权投入 |
| **E3** | 真实竞品/市场状态 | 竞品实际产品界面与定价、公开财报、真实采购案例 | 可校正机会与商业假设 |
| **E4** | 内部一线记录 | 销售通话记录、运营观察、客服归类、客服/销售一线反馈 | 可提出假设；需 E1/E2 验证 |
| **E5** | 二手研究/专家判断 | 行业报告、顾问框架、类比推理 | 仅供形成假设 |
| **E6** | 本团队推断 | 会议室共识、"大家都觉得"、老板自己的想法 | **永远不能单独通过任何门控** |

**硬规则：**
- 任何门控的通过结论（GO / CONDITIONAL），至少要有 **一条 E1 或 E2** 支撑。
- 授权"上线/扩大投入"的门控（阶段 14 / 16 / 17 / 18 的 GO），必须有 **一条 E1**。
- 只有 E5/E6 支撑 → 门控结论只能是 `证据不足`，不是"通过"，也不是"失败"。
- 报告反面证据与支持证据同权；只呈现支持证据的阶段记录视为不合格。

**E5/E6 的正确用法（2026-10-24 前向测试修订）：**

E5/E6 **必须记录**，但**不能承载门控**。这两件事不能混：

| | 能不能写进证据表 | 能不能作为门控支撑 |
|---|---|---|
| E5 二手研究 | 能 | 不能 |
| E6 本团队推断 | 能 | 不能 |
| E1/E2 | 能 | 能 |

理由：E6 往往就是**这个项目为什么开始**（老板的想法、一次内部会议），
它是记录里必须留痕的一部分。校验脚本**不得**因为它不能支撑门控就禁止作者写它——
那会逼作者删掉真实的发起信号，或把它错标成 E2，两种都比"标着 E6 但注明不作支撑"更糟。

所以校验脚本的规则是：
- 记录里有 E5/E6 行 → **警告**（"可记录，但不能承载门控结论"），不报错。
- 裁决是 GO / CONDITIONAL 而记录里没有 E1/E2 → **报错**。
- CONDITIONAL 允许"证据还不够"：只要在「未闭合前置条件」里点名缺的是 E1/E2 证据，就算合规。
- REVISE / STOP 不设证据下限——那正是契约里的 `证据不足` 分支，没有证据也是正当理由。

## 3. 四种门控裁决

每个阶段的门控只允许这四种结论，且必须写清触发条件：

| 裁决 | 含义 | 必须写明 |
|---|---|---|
| **通过 GO** | 证据达标，进入下一阶段 | 依据的证据编号、下一阶段负责人 |
| **有条件通过 CONDITIONAL** | 方向对，但有未闭合的前置条件 | 条件清单 + 闭合期限 + 未闭合时的动作（降级/延期/回滚） |
| **返工 REVISE** | 判断本身不成立或证据不足，回到本阶段某一步 | 缺什么证据、谁去补、什么条件下重来 |
| **终止 STOP** | 不成立、机会不足或不可接受风险 | 终止理由、已投入沉没、是否留监控再启 |

**反模式：把"证据不足"写成"通过"。** 用户流程原文明确要求："不得把'没有显著失败'直接当作成功。"
本契约把"证据不足"单列为 REVISE 的一个分支，判定话术固定为：
`证据不足 — 缺 E1/E2 证据 X，补齐后重开本阶段门控`。

## 4. 阶段记录卡（每阶段一份，固定字段）

每阶段结束必须产出这张卡，字段不可删（可写"无"并说明原因）：

```
阶段：<编号 名称>
负责人：
关键问题：<本阶段唯一要回答的问题>
证据来源：<E1-E6 分级 + 来源/时间/口径/样本/限制>
结论：<支持证据 + 反面证据>
未决假设：<还剩哪些假设没被证伪>
门控裁决：GO / CONDITIONAL / REVISE / STOP
继续条件：
暂停条件：
调整条件：
终止条件：
下一步动作 + 负责人 + 期限：
```

**记录质量三条硬标准**（`scripts/gate_check.py` 会自动校验）：
1. 证据必须带**来源 + 时间 + 口径 + 样本**四项，缺任一即判定不可追溯。
2. 必须同时出现**支持证据**和**反面证据**两段；只有支持证据 → 校验失败。
3. 门控裁决必须落在四种之一，且"继续/暂停/调整/终止"四个条件字段都不能为空。

**按阶段加严（发布类门控）**：阶段 14（试点）、16（发布）、17（监测）、18（规模化）的
GO 裁决授权真实用户使用，必须额外有 **一条 E1**。E2（用户原话）能证明"痛点真实"，
但证明不了"上线后指标达标"。这四个阶段的卡如果只有 E2，校验脚本会直接报错。

## 5. 风险红线贯穿全程

红线在**阶段 1 就要开始识别**，在**阶段 13/14 之前必须固化为可执行的发布红线**。
一条合格的红线必须写全四项，缺一项就不算红线：

```
触发条件（可观测的具体事件，如"试点组退款率 > 基线 +3pp"）
监测方式（谁看、看板在哪、多久看一次）
负责人（具体的人，不是"团队"）
处置动作（停止试点 / 限制范围 / 回滚 / 降级，二选一以上写清顺序）
```

反例：「注意安全」「关注用户反馈」——没有触发条件、没有动作，等于没写。

## 5b. 门控要有责任主体

一条记录卡如果没有"谁对这个门控负责"，就不算门控，只是建议。

- **负责人 / 复核人必须指向具体的人。** 「代持」「待指派」「某某」「产品团队」「待老板指派」
  都不算——这些写法等于没人负责。校验脚本会直接判不通过。
- 确实暂时没有人负责，就写 **「无」并补一句原因**，让缺口可见；不要写占位说法蒙混。
- 写了具体的人但附带「代持」「待指派」等说明 → 只给**警告**，不判失败：
  这种写法是诚实的（记录了"谁暂时顶这件事"），不该被脚本逼着改成假名字。
- 高风险决策（卡片里写明「风险等级：高」或复核人标注必填）必须有具名复核人。

> 同一个原则贯穿本契约：**脚本不能逼作者写假东西。** 能软化的问题给警告，
> 只有"这张卡不可用"才算错误。

## 5c. 校验脚本的设计准则（2026-10-24 前向测试血泪）

`scripts/gate_check.py` 是这个工作流的执行者，也是最容易变成"表格官僚"的地方。
前向测试（真实跑阶段 1）暴露了一个反模式，值得写死：

**硬判 E6 失败，会逼作者删掉真实的发起信号。**
旧版脚本对任何 E6 行直接报错，于是记录卡作者（当时就是我）把"老板的想法"这一行
从证据表里**拿掉了**，只在结论里提一句"发起信号为 E6"。这不是遵守规则，
这是规则逼人造假——真实发生过的事被从记录里抹掉了，比留着一条标着 E6 的行更糟。

所以脚本改成：

| 情况 | 处理 | 为什么 |
|---|---|---|
| E5 / E6 行存在 | **警告**，不报错 | 它是真实发生过的事，必须留痕；只是不承载门控 |
| GO / CONDITIONAL 但无 E1/E2 | **报错** | 通过门控必须有真实证据 |
| CONDITIONAL 且在「未闭合前置条件」点名缺的 E1/E2 | 通过 | "方向对但证据还不够"是正当裁决 |
| REVISE / STOP 且证据不足 | 通过 | 这正是契约里的"证据不足"分支 |
| 负责人/复核人只写得出占位说法 | **报错** | 没人负责的门控不是门控 |
| 负责人写了人但附带"代持/待指派"说明 | **警告** | 诚实的写法，不该逼人改成假名字 |
| 阶段 1 缺「候选问题陈述」表 | **警告** | 阶段 1 的产物本该有，但不该因此卡死 |
| 阶段 1 的 CP 表存在但问题陈述为空 | **报错** | 表在，就必须填 |
| AI 适用性初判六项未作答 | **报错** | AI 产品不做这个初判，等于没审过 AI 适不适合 |
| AI 是否是价值点答"否"但裁决 GO | **警告** | 价值不在 AI 就得说清价值到底在哪 |
| 缺「产物」区块 | **报错** | 没有落盘的产物 = 阶段白做，下次无法复用 |
| 机会成本表只有 1 个候选（阶段 5/6/16） | **报错** | 只比较一个选项等于没做选择 |
| 机会成本表缺失（阶段 5/6/16） | **警告** | 缺表要说，但不该卡死整张卡 |
| 品味对照表无参照物行（阶段 9/11） | **报错** | 没有参照物的判断是偏好不是判断 |
| 品味对照区块缺失（阶段 9/11） | **警告** | 同上 |
| 硬标准未作答 + 裁决 GO（单位经济/合规/AI 评测） | **报错** | 带空表 GO = 这张卡不可用 |
| 硬标准未作答 + 裁决 REVISE/CONDITIONAL | **警告** | 点名缺口是正当裁决 |
| 合规项仍有「待确认」+ 裁决 GO | **报错** | 待确认必须降为 CONDITIONAL |
| 缺「评估集」区块（AI 阶段 8/9） | **警告** | 老卡片没有这个区块，不该直接判死 |
| 「评估集状态」= 未建立 + 裁决 GO（阶段 8/9） | **报错** | 没有评估集规格的 AI 产品不能 GO |
| 评估集区块存在但九项未填全 | **报错** | 表在就必须填 |
| 阶段 13 GO 但 AI 评测工程未填 | **报错** | 没有回归门禁的 AI 产品，"上线准备"不得 GO |
| 未标可逆性（R1–R4） | **警告** | 老卡片不判死，但难逆决策必须标出来 |
| 「可逆性」写了非 R1–R4 的值 | **报错** | 等级写错等于没分级 |
| 可逆性 R3/R4 但复核人未具名 | **报错** | 难逆决策不能一个人拍板 |
| 可逆性低于阶段默认（且无理由） | **警告** | 标更易逆是允许的，但要写清为什么 |
| 有「门控例外」但授权人只写得出"老板/领导/团队" | **报错** | 没有具名授权人 = 没有授权 |
| 有「门控例外」但缺「被跳过的证据要求」 | **报错** | 不知道跳过了什么，就无法补 |
| 有「门控例外」但缺补救期限或补救责任人 | **报错** | 绕过是延后，不是取消 |
| 门控例外区块原裁决为 STOP/REVISE 但未说明「为什么仍然推进」 | **报错** | 绕过终止结论必须写明理由 |
| 未填「本次判断不承诺什么」 | **警告** | 卡做完了不等于结论被证明 |
| 未填「决策者自问」 | **警告** | 反方协议只问外部角色，缺决策者自己的盲区 |
| 「我的位置」写"我没有私心"这类断言 | **警告** | 断言无偏见等于没回答 |
| 门控成本无数字 / 写"很快就结束" | **警告** | 秒过不是高效，是没做判断 |
| 证据「样本」栏写量词（多/若干/一些） | **警告** | 写具体数字或可数的范围 |
| 证据「时间」栏无具体日期或时间窗 | **警告** | 不可追溯 |
| 证据「来源」栏只写材料类型（报告/文档）无路径或 URL | **警告** | 无法追溯到具体一份 |
| 反面证据写"暂未发现"但没写搜索范围 | **警告** | 「没找到」必须说清在哪找的 |
| 风险红线区块无红线行且未写「不适用 + 理由」 | **报错** | 确实没有红线就写不适用并说明理由 |

**判据：报错 = 这张卡不可用；警告 = 这张卡能用但有话要说。**
凡是"作者可以诚实地写下来却被脚本判失败"的规则，都要降级成警告。

**同一条原则在"硬标准"上的体现**：未作答的单位经济表在 REVISE 下只是警告
（点名缺口是正当裁决），在 GO 下才是错误——带空表说"可以发布"，
这张卡就没有承载它声称的那个结论。

## 6. 阶段间的追溯链

- 每个阶段的结论必须能追到**上一阶段的产物**，上一阶段的未决假设若被本阶段证据推翻，
  必须显式标注"已推翻/已确认"，不能静默丢弃。
- 阶段 12（开发执行）发现新证据改变原判断时，**必须回到阶段 5/6 重评**；
  不允许以"已经投入开发"为由自动继续。这是硬约束，不是建议。

## 7. 时间盒默认值

没有明确安排时使用下列默认值，超出即在记录卡里写明为何延长：

| 阶段类型 | 时间盒 | 产出下限 |
|---|---|---|
| 快速判断类（1、2、5、7、16、19） | 1–2 个工作日 | 一页裁决备忘录 |
| 研究类（3、4、6、8、9） | 1–2 周 | 结论 + 证据表 |
| 交付类（11、12、13） | 随迭代 | 需求 + 验收条件 + 记录卡 |
| 试点类（14、15） | 2–6 周 | 预注册阈值 + 结果解读 |
