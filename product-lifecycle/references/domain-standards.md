# 领域硬标准 — 三件「不补会死」的事

**为什么单独成文件**：这三件事在 20 阶段流程里**没有对应的阶段**，但缺了产品会死。
它们不是"某个阶段的任务"，是**贯穿全程的硬标准**，在特定阶段被强制检查。

| 标准 | 强制检查点 | 缺了会怎样 |
|---|---|---|
| §1 单位经济 | 阶段 4 / 16 / 18 | 规模化后才发现不赚钱 |
| §2 合规红线 | 阶段 10 / 13 / 16（AI 产品必查） | 上不了线 / 罚款 / 下架 |
| §3 AI 评测工程与质量漂移 | 阶段 9 / 13 / 17 / 20 | 静默劣化，用户悄悄流失 |

---

## 1. 单位经济（Unit Economics）

**强制阶段**：阶段 4（市场与商业假设）、阶段 16（发布决策）、阶段 18（规模化）。

### 必须产出的表

```
获客成本 CAC = 获客总支出 / 新增付费用户数
LTV = ARPU × 平均付费月数 × 毛利率
回本周期 = CAC / (ARPU × 毛利率)   ← 单位：月
LTV/CAC ≥ 3（ToB 定制交付看 毛利/获客成本 ≥ 3）
回本周期 ≤ 12 个月（B 端） / ≤ 6 个月（C 端）
月度推理成本 = 单次调用成本 × 月调用次数 × 月活跃用户数
毛利率 = (收入 - 推理成本 - 履约成本) / 收入
```

### 三个最容易算错的地方

1. **CAC 的分母要写清**。是"新增付费用户"还是"新增注册"？差一个数量级。
2. **推理成本必须随规模算**。AI 产品的边际成本不为零，规模化的成本曲线可能**先降后升**
   （缓存命中率下降、复杂请求占比上升、长上下文占比上升）。不能假设线性摊薄。
3. **回本周期分母要用毛利率**，不是收入。用收入算会乐观 3-5 倍。

### 门控规则

- 阶段 4 的 GO：**必须有单位经济表**，且每个数字有来源（报价单 / 账单 / 竞品公开定价 / 自有数据）。
- 阶段 16 的 GO：**必须回到阶段 4 的表并更新实际值**，不能沿用估算而不标注。
- 阶段 18：**必须找到规模不经济拐点**——在什么用户量/调用量下毛利率跌破底线？写不出拐点的规模化计划不可执行。
- **数字是估算 → 必须写成区间 + 依据**，不许写点估计。区间的下界也要过线才算 GO。

> **门控话术**：单位经济不成立 → `REVISE — 缺单位经济表（至少 CAC / 回本周期 / 毛利率三项），
> 补齐后重开本阶段门控`。不是"先上线再说"。

## 2. 合规红线

**强制阶段**：阶段 10（可行性与风险）、阶段 13（上线准备）、阶段 16（发布）。

### 中国境内 AI 产品必查清单

| 项 | 适用 | 怎么确认 | 门控影响 |
|---|---|---|---|
| **算法备案 / 算法推荐服务备案** | 有推荐、排序、生成类算法并对境内公众提供服务 | 国家互联网信息办公室算法备案系统，记录备案编号 | **未备案 → 阶段 16 不得 GO** |
| **生成式 AI 服务备案 / 登记** | 面向境内公众提供生成式 AI 服务 | 网信办生成式 AI 服务备案清单，登记编号 + 日期 | 同上 |
| **深度合成内容标识** | 生成/合成内容对外发布 | 内容显式 + 隐式标识（见《深度合成管理规定》） | 未实现 → 不得上线 |
| **训练数据来源合法性** | 用了他人内容训练 | 授权凭证 / 公开许可协议 / 自有数据 | 无法说明 → 阶段 10 不得 GO |
| **个人信息保护合规** | 处理个人信息 | 告知同意、最小必要、去标识化 | 见下 |
| **数据出境安全评估** | 用境外服务处理境内用户数据 | 评估/标准合同备案 | 未完成 → 不得上线 |
| **内容安全审核机制** | 生成式内容 | 关键词/分类器 + 人工复审 + 举报入口 | 无机制 → 不得上线 |
| **未成年人保护** | 面向未成年人 | 单独策略 + 内容分级 | — |

**硬规则**：
- **引用必须到原文条款**：《生成式人工智能服务管理暂行办法》第 X 条 + 链接 + 访问日期。
  不接受二手解读、行业文章、律师公众号摘要作为合规依据。
- **不能确定是否适用** → 写「未确认 + 谁能确认 + 期限」，**不能留空**。留空 = 未查。
- **备案编号要落到记录卡的「证据来源」表**，等级 E3（真实市场/监管状态），作为 GO 的支撑之一。

### 个人信息与研究材料的采集合规

这一条同时管住 `evidence-discipline.md` 的取证环节：

- 用户数据（姓名/手机/订单号/地址/原始会话）**脱敏后**才进工作区，原始文件不进版本库。
- 只用于本次研究，**不外传、不二次营销**；对外引用一律用去标识片段。
- 公开帖子：**可引原话 + 链接**，不可把作者身份与推断结论绑定传播。
- 付费意愿调查必须标注样本来源与是否付费。

### 门控规则

- 阶段 16 的 GO：**合规状态必须逐项列出**（"适用/不适用/待确认 + 证据编号"），
  出现一个"待确认" → 降为 CONDITIONAL，并写清闭合期限与责任人。
- 阶段 13 的上线准备：安全与合规项未闭环 → **不得 GO**。

## 3. AI 评测工程与质量漂移

**强制阶段**：阶段 8 / 9 / 10 / 13 / 14 / 17 / 20（AI 产品）。

**完整规范见 `references/ai-evals.md`** —— 四层评估集结构、分层抽样、判分器人工校准、
逐切片阈值与 CI 下界、失败模式分类学、回归 CI 门禁与基线版本化、成本-质量 Pareto、
10 条反模式。**开始任何 AI 阶段之前先读它**，本节只给门控视角的摘要。

**为什么单独拎出来**：传统产品的 bug 会**报错**，AI 产品的 bug 常常**静默劣化**——
模型更新、prompt 微调、检索排序变更、上下文截断策略调整，都会让质量下降而用户不报错，
只是慢慢不来。产品经理从仪表盘上看到的只是"留存缓降"，找不到原因。

### 3.1 门控摘要

| 阶段 | 必须交付 | GO 的前置条件 |
|---|---|---|
| 8 验证计划 | eval 集规格书（四层 + 切片表 + 判分方式 + 校准计划） | 无规格 → 不得 GO |
| 9 方案验证 | 首轮评测（逐切片 + CI 下界 + 失败模式分布）+ 与非 AI 基线对照 | 无首轮结果，或任一切片 0 分 → 不得 GO |
| 10 可行性 | 单位成本模型 + 延迟预算 + 成本-质量 Pareto 初步曲线 | 无成本上限 → 不得 GO |
| 13 上线准备 | **回归门禁配置 + 基线版本号** + 影子模式对比 + kill switch 演练 | 无基线或无回滚 → 不得 GO |
| 14 试点 | 试点期线上指标（采纳率 / 人工改写率 / 拒答率 / 升级率）+ 回归集回流 | 有安全切片失败 → 不得 GO |
| 17 监测 | 质量漂移监控 + 每次模型变更的回归报告 | 无漂移监控 → 不得 GO |
| 20 AI 审计 | 全量审计报告（逐切片 + 失败模式 + 偏差 + 滥用 + 人工接管 + 成本） | 失败可控才 GO |

### 3.2 CI 回归门禁（最关键的一条）

**任何**下列改动，都必须重跑黄金集 + holdout：

- prompt 改动（含 few-shot、system prompt、输出格式）
- 模型 / 模型版本切换
- 检索策略、排序、chunk 切分、embedding 变更
- 温度、max_tokens、工具调用配置

**阻断规则**：**以 `references/ai-evals.md` §4.2 为准**（那是阈值的唯一真身），
`scripts/eval_stats.py gate` 机械执行。本文件不重复写数字——两处各写一份，
迟早会漂成两个互相矛盾的数字。

**规则**：**没有 CI 回归门禁的 AI 产品，其"上线准备"结论一律不得为 GO。**
这是阶段 13 的硬门槛，与回滚演练同级。

**基线必须版本化**：eval 集 + 判分脚本 + 基线分数三者一起存档。
没有版本化的基线，回归对比就是"我记得以前好像还行"。

### 3.3 漂移监控（上线后）

| 监控项 | 怎么测 | 触发动作 |
|---|---|---|
| **输入分布漂移** | 线上真实输入 vs 黄金集输入分布，按切片维度分桶比对 | 某桶占比变化 > 10pp → 触发重测 + 补样本 |
| **质量抽检** | 每周抽 N 条线上真实输出人工评分 | 连续两周下降 > 5pp → 触发回归排查 |
| **人工升级率** | 转人工 / 人工改写比例 | 上升 → 模型或输入分布变化 |
| **拒答/兜底率** | 触发降级路径的比例 | 上升 → 覆盖不足 |
| **单位成本** | 每次调用成本 × 调用量 | 上升 > 20% → 排查上下文长度 / 重试 |
| **高风险事件** | 安全/合规类异常输出 | 任何一例 → 立即上报 + 考虑降级 |

**规则**：漂移监控的判据必须**事前写死**在阶段 8 的验证计划里，不能上线后再定。

### 3.4 成本-质量帕累托

每次版本变更，记录两列：**质量分 + 单位调用成本**。
只提质量不提成本的改进，如果成本翻倍，**不算改进**。
在仪表盘上画出帕累托前沿，**拒绝任何让前沿恶化的改动**。

### 3.5 判分器校准（judge 不是标尺，是需要校准的仪器）

用 LLM-as-judge 当门控证据，必须先做人工校准。**完整流程见 `references/ai-evals.md` §2.2**
（该文件是这一步的唯一真身），机械执行：

```bash
python3 scripts/eval_stats.py kappa <judge.jsonl> <human.jsonl>
```

**rubric 改版 = 全部历史分数作废重跑。** rubric 版本必须和分数一起存档。
