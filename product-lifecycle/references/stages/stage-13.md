### 适合场景
功能完成；准备进入试点或正式发布。

### 目标
确认核心任务可用、稳定，数据正确，支持与回滚就绪，并给出**明确的上线结论**。

### 要回答的问题
1. 核心任务是否可用、稳定？
2. 数据与埋点是否**被验证正确**（不只是"已实现"）？
3. 支持流程、文档、升级路径是否就绪？
4. 回滚是否**演练过**，不是写在文档里？
5. 试点范围与回滚条件是什么？

### 关键问题
> **如果现在必须回滚，我们能在几分钟内回到可用状态吗？谁有权限执行？**
> 这题答不上 → 不许上线。

### 方法论
发布就绪度分职能检查（产品/工程、市场、支持、销售、数据），
每个职能给 就绪 / 有风险 / 阻塞 三档 + 证据；阻塞项必须有具体责任人和截止时间。

### 判断标准
| 判据 | 达标线 |
|---|---|
| 核心任务 | 关键路径任务端到端跑通，有测试记录 |
| 缺陷 | 无严重缺陷；已知问题有分级与处置 |
| 数据 | 埋点在 staging **验证过**，不是仅实现 |
| 支持就绪 | FAQ/文档已发布，支持团队已培训，升级路径定义 |
| 回滚 | 已在 staging **演练过**，有执行人与耗时估计 |
| 试点范围 | 写明试点人群、范围、期限、观察指标、护栏、停止条件 |
| 决策 | Go / Conditional Go / No-Go 三档，附理由与决策人 |

### 工作内容
1. 走 launch-readiness 全清单，按职能打档并附证据。
2. 收集并分级缺陷，阻塞项逐条定责任人 + 截止时间。
3. **在 staging 验证埋点**（拉真实数据核对）。
4. 支持就绪：FAQ、文档、培训、升级路径。
5. **演练回滚**，记录实际耗时与执行人。
6. 写试点定义（人群/范围/期限/指标/护栏/停止条件）。
7. 给 Go / Conditional Go / No-Go 结论。

- 试点定义（范围/期限/指标/护栏/停止条件）
- 上线结论（Go / Conditional Go / No-Go）

### 质量标准
- 没有证据的职能不打"就绪"。
- Conditional Go 必须写清"什么条件、谁、什么时候"，含糊的条件不算条件。
- 阻塞项不能挂在"团队"名下，必须有单一责任人。
- 埋点未在 staging 验证 = 上线不可评估 = 不许上线。

### AI 专项工作（仅 AI 产品适用）

**要回答的问题**
1. 评测基线版本号存在吗？能复现出同一个分数吗？
2. 关键切片（含安全切片）都过了吗？
3. 安全边界测了吗——注入、越权、隐私串号、格式？
4. 峰值负载下的成本与 P95 延迟是多少（不是平均值）？
5. 回滚演练做了吗——能回滚模型版本，也能一键退回人工？
6. 人工接管真触发过一次吗，耗时多少？

**关键问题**
> **如果必须现在停掉这个 AI 功能，用户会不会直接撞墙？** 会 → 降级路径没演练过。

**方法论**
AI 就绪度清单：基线校验 → 切片校验 → 安全边界 → 峰值负载 → 回滚与降级演练 → 接管演练。
每项要证据（截图/日志/计时），不是打勾。

**判断标准**
| 判据 | 达标线 |
|---|---|
| 基线 | 版本号存在且两个不同人跑出同一个数字 |
| 切片 | 安全切片容忍度 0，任一失败即阻断 |
| 安全边界 | 注入/越权/隐私串号/格式各有测试记录 |
| 峰值 | 峰值负载下的成本与 P95，不是平均值 |
| 回滚 | 模型版本可回滚 + 一键降级到人工，均已演练并计时 |
| 接管 | 真实触发一次并计时 |

**工具**
`$PM/moh/skills/launch-readiness/SKILL.md` ·
`$PM/moh/skills/monitoring-setup-guide/SKILL.md` ·
`$PM/moh/skills/incident-postmortem/SKILL.md` ·
`python3 scripts/eval_stats.py gate ...`

**工作内容**
1. 校验评测基线版本（复现性 + 关键切片结果）。
2. 跑安全边界测试并留记录。
3. 压测：峰值负载下的成本与 P95 延迟。
4. 演练回滚（模型版本）与降级（退回人工），记录耗时与执行人。
5. 演练一次人工接管，记录接管路径与耗时。
6. 确认 kill switch 可用（关掉 AI 能力不影响核心流程）。

**原始材料与来源**
阶段 12 的 CI 评测结果与基线版本、压测记录、回滚与接管演练记录。

**优先证据**
- **E1**：staging 上的真实评测分数、压测数据、演练计时
- **E4**：支持与运维对 AI 故障处置的确认

**产物**
- AI 就绪度报告（并入上线就绪度报告）
- 回滚与降级演练记录
- 人工接管演练记录

**质量标准**
- 没有证据的项不打"就绪"。
- 演练要有实际耗时与执行人，不是"计划演练"。
- 安全切片任一失败 = 阻塞项，不是备注。

**门控补充条件**
- **无回归基线版本号 → 不得 GO**（没有基线就没有"退化"这个概念）。
- **无 kill switch 或降级路径未演练 → 不得 GO。**

### 决策门控
- **通过 GO** → 阶段 14 最小试点 / MVP 验证。
- **有条件通过 CONDITIONAL** → 有条件上线（限范围）+ 条件与期限。
- **返工 REVISE** → 严重缺陷或测量失效 → 暂停发布，修复后重开本阶段。
- **终止 STOP** → 核心任务不可用或回滚不可行 → 回阶段 10/12。
