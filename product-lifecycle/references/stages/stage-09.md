### 适合场景
验证计划就绪；需要产出并比较具体方案。

### 目标
产出多个候选方案，用最低保真度方式验证理解度、采用意愿与价值获取。

### 要回答的问题
1. 哪些方案能真正解决那个已验证的问题？
2. 用户能理解吗？能完成核心任务吗？愿意用吗？
3. 用户真的获得价值，还是只是"觉得不错"？
4. 选定哪个方案，剩余风险是什么？

### 关键问题
> **用户完成核心任务时在哪一步卡住了？**（"喜欢"不是证据，"独立完成"才是）

### 方法论
原型与可用性测试、概念测试、假门测试、人工模拟服务（Wizard of Oz）、技术概念验证。
方案比较表统一维度：问题覆盖度 / 用户可理解性 / 成本 / 风险 / 可扩展性。

### 判断标准
| 判据 | 达标线 |
|---|---|
| 问题覆盖 | 每个方案明确标注覆盖了已验证问题的哪一部分 |
| 可用性 | 至少一次任务级测试，有完成率与卡点记录 |
| 采用意愿 | 有行为性信号（点选/预约/试用），不是口头"会用" |
| 价值获取 | 能指出用户获得价值的可观测证据 |
| 比较基础 | 所有方案用同一套维度与同一批证据比较 |
| 风险登记 | 落选方案写明"它赢在哪/输在哪"，不是删除 |

### 工作内容
1. 基于已验证问题生成 2–3 个候选方案（不是功能列表，是问题解法）。
2. 为每个方案做最低保真度原型（纸面/点击流/假门/人工后端皆可）。
3. 跑可用性测试：5–8 人，记录完成率、卡点、原话。
4. 用统一维度表比较，写清选定理由与落选理由。
5. 登记剩余风险（哪个假设仍未被证伪）。

### 原始材料与来源
阶段 3 的问题陈述与场景、阶段 6 的边界、阶段 8 的验证计划、竞品实际产品体验作为体验基准。

### 优先证据
- **E1**：任务完成率、卡点位置、原型上的行为记录
- **E2**：用户口述的困难与替代动作
- **E3**：竞品同类流程的真实设计（作为可用性参照）

### 产物
- 方案比较表（统一维度 + 证据）
- 可用性测试记录（完成率 / 卡点 / 原话）
- 选定方案 + 剩余风险清单
- **AI 产品：首轮评测结果** → `artifacts/10-eval-plan.md`（逐切片通过率 + CI 下界 + 失败模式分布 + 与非 AI 基线的对照）
  **没有首轮结果，或任一切片通过率为 0 → 本阶段不得 GO**（见 `ai-evals.md` 第 7 节）。

### 质量标准
- 原型保真度与学习目标匹配：需要理解流程就别做高保真动画。
- 每条结论能追到一条测试记录。
- 落选方案保留（含落选理由），供后续回看。
- **AI 产品**：逐切片单独报通过率，**安全切片容忍度 0 且不进任何平均值**；
  成对比较用胜率 + CI 下界，不用绝对分。
- 明确指出哪些指标还是"不可信"（数据不够）。

### AI 专项工作（仅 AI 产品适用）

**要回答的问题**
1. 换个基模会怎样？——同一批任务上不同基模的质量、成本、延迟差多少？
2. Prompt / RAG / 工作流 / Agent 四条技术路线，各自适合这个任务吗？
3. 和非 AI 基线（规则/搜索/人工/模板）比，AI 赢在哪、输在哪？
4. 在真实分布的任务上，质量与成本各是多少？

**关键问题**
> **如果一个基模就能解决问题，为什么要上 Agent？** 复杂度要有对应的收益证据。

**方法论**
同评估集上的基模对比（成对胜率 + CI 下界，不用绝对分）＋四条技术路线各做最小原型
＋非 AI 基线对照 ＋代表性任务测量质量与成本。

**判断标准**
| 判据 | 达标线 |
|---|---|
| 基模对比 | ≥2 个基模，同一评估集同一 rubric |
| 路线验证 | 四条路线各有最小原型与失败模式 |
| 非 AI 对照 | 同一维度表对照，赢在哪/输在哪都写 |
| 代表性任务 | 真实分布抽样，不是自编简单题 |
| 结论 | 选定方案 + 剩余风险 |

**工作内容**
1. 在方案比较表里把"技术路线"升成一列：Prompt / RAG / 工作流 / Agent。
2. 同一评估集跑 ≥2 个基模，报成对胜率 + CI 下界。
3. 每条路线做最小原型，记录它自己的失败模式（不是只记录最好的那条）。
4. 与非 AI 基线做同维度对照。
5. 用代表性任务测质量与成本，产出首轮评测结果。

**原始材料与来源**

**优先证据**

**产物**

- 成对比较用胜率 + CI 下界，不用绝对分。
- 落选路线保留落选理由，供后续回看。

**门控补充条件**

### 决策门控
- **通过 GO** → 阶段 10 评估可行性、风险与交付范围。
- **有条件通过 CONDITIONAL** → 结果混合 → 调整原型再测一轮（有条件通过）。
- **返工 REVISE** → 核心价值假设失败 → 回阶段 5 方向选择。
- **终止 STOP** → 方案都无法解决已验证问题 → 回阶段 3 重新定义问题。
