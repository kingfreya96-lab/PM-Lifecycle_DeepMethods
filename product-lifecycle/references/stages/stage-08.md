### 适合场景
指标已定；需要决定"先验证哪个假设、怎么验证、什么结果算失败"。

### 目标
把关键假设变成**可证伪**的验证计划：方法、样本、周期、阈值、停止条件、偏差清单。

### 要回答的问题
1. 我们最不确定、且一旦错了代价最大的假设是哪一个？
2. 用什么证据能最快、最便宜地判断它真假？
3. 什么结果算成功 / 失败 / **证据不足**（三态，不许二态）？
4. 样本要多少、跑多久？谁执行？
5. 这个设计有哪些已知偏差（选择偏差、安慰剂效应、幸存者偏差）？

### 关键问题
> **这次验证如果"失败了"，我们会做什么？** 答不出 → 这个假设不重要，先去测更重要的。

### 方法论
按假设类型选方法：需求 → 访谈/假门测试；易用性 → 原型可用性测试；价值 → 概念测试/落地页；
技术 → 技术概念验证/假门；商业 → 定价测试/预售；运营 → 人工模拟服务（Wizard of Oz）。
条件允许时用对照设计。PoL probe（Proof of Life）优先于 MVP——**做出来是为了删掉的**。

### 判断标准
| 判据 | 达标线 |
|---|---|
| 假设可证伪 | 每条假设写成"若 X 则 Y"，能被单一实验判定 |
| 三态阈值 | 每条假设都有成功/失败/证据不足三个阈值 |
| 样本与周期 | 写明样本量来源与最短观察期 |
| 停止条件 | 明确什么情况立刻停，不等跑完 |
| 偏差登记 | 至少列出 2 条已知偏差及其影响方向 |
| 优先级 | 假设按"影响 × 不确定性"排序，先测最上面的 |

### 工作内容
1. 从阶段 6 假设表取关键假设，按影响×不确定性排序。
2. 每条假设写：若 X 则 Y + 验证方法 + 样本/周期 + 成功/失败/证据不足阈值 + 停止条件。
3. 选验证方法时问："最便宜的诚实实验是什么？"
4. 登记偏差（至少 2 条）与它们对结论方向的影响。
5. 排验证顺序与依赖，指定负责人与截止日期。

### 原始材料与来源
阶段 6/7 的假设表与指标口径、已有实验的样本量与显著性经验、历史失败实验的教训。

### 优先证据
- **E1**：历史同类实验的真实样本量与转化率基线（用于样本量估算）
- **E2**：小样本定性反馈（用于生成假设，不用于判定阈值）
- **E5**：方法论文档

### 产物
- 假设验证计划表（假设 / 方法 / 样本 / 周期 / 三态阈值 / 停止条件 / 负责人）
- 已知偏差清单
- 验证顺序与依赖图
- **AI 产品：评估集规格书** → `artifacts/10-eval-plan.md`（四层评估集 + 切片表 + 判分方式 + 判分器校准计划 + 逐切片阈值 + 回归基线版本）
  **AI 产品没有评估集规格 → 本阶段不得 GO**（见 `ai-evals.md` 第 7 节）。

### 质量标准
- 每条假设都有"证据不足"分支。
- 停止条件是**可执行的**（"退款率 > 基线+3pp 立即停"），不是"感觉不对就停"。
- 假设编号与阶段 6 一致，可追溯。
- 样本量有计算依据或明确写"探索性，无统计功效承诺"。
- **AI 产品**：黄金集来源必须是生产 trace（不是自己出题）；切片表覆盖失败模式；
  判分器若用 LLM-as-judge，必须写明校准计划（n、κ、一致率门槛 κ≥0.80）。

### AI 专项工作（仅 AI 产品适用）

**要回答的问题**
1. 用什么证据判断 AI 假设成立——模型评测够，还是必须加端到端产品评测？
2. 每条 AI 假设的成功/失败/证据不足三个阈值分别是什么？
3. 评估集从哪来、覆盖哪些切片、谁来判分、判分器校准了吗？
4. 什么情况下停止这个 AI 方案？

**关键问题**
> **如果模型侧指标全绿但用户端任务没做成，这次验证会告诉我们吗？**

**方法论**
模型评测（四层评估集 + 切片表 + 判分器校准，见 `references/ai-evals.md`）
＋端到端产品评测（真实任务流成功/失败 + 人工改写率 + 采纳率）＋三态阈值。

**判断标准**
| 判据 | 达标线 |
|---|---|
| 评估集 | 四层结构 + 切片表，来源是生产 trace 分层抽样 |
| 判分可信 | judge 经人工校准（n、κ、一致率、日期、rubric 版本） |
| 端到端 | 有独立于模型指标的任务级评测设计 |
| 三态 | 每条 AI 假设三态阈值齐全 |
| 停止条件 | 可执行（"合规切片失败即停"） |

**工具**
`references/ai-evals.md` 全文 · `$PM/moh/skills/experiment-designer/SKILL.md` ·
`$PM/moh/skills/ai-ethics-review/SKILL.md`

**工作内容**
1. 从阶段 6/7 取 AI 假设，按"影响 × 不确定性"排序。
2. 设计模型评测：四层评估集 + 切片表 + 判分方式 + 判分器校准计划。
3. 设计端到端产品评测：任务完成、人工改写率、采纳率怎么测。
4. 每条 AI 假设写三态阈值 + 停止条件 + 责任人。
5. 登记 AI 特有的偏差（评测集不具代表性、judge 偏差、只看好例子）。

**原始材料与来源**
阶段 7 的失败模式清单与阈值、生产 trace 抽样、历史模型评测的教训。

**优先证据**
- **E1**：真实生产 trace 的分布与失败率（决定评估集怎么抽）
- **E2**：用户对 AI 输出质量的具体抱怨（生成失败模式候选）

**产物**
- **AI 评估集规格书** → `artifacts/10-eval-plan.md`
- 端到端产品评测设计（并入验证计划）
- AI 假设三态阈值表

**质量标准**
- 评估集来源必须是生产 trace，不是自己出题。
- 用 judge 就必须写校准计划（n、κ≥0.80 或一致率≥85%）。
- 端到端评测独立于模型指标，不是同一个数据的两种说法。

**门控补充条件**
- **无评估集规格 → 本阶段不得 GO**（见 `ai-evals.md` §7）。

### 决策门控
- **通过 GO** → 阶段 9 探索并验证方案。
- **有条件通过 CONDITIONAL** → 计划缺少某项测量条件（数据/样本/人力）→ 补条件再进。
- **返工 REVISE** → 无法区分关键假设（例如方法对所有假设都太钝）→ 重新设计。
- **终止 STOP** → 无任何可行的低成本验证路径 → 回阶段 5/6。
