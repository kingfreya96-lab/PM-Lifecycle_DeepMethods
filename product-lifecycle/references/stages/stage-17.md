### 适合场景
已发布，进入运行期。

### 目标
确认价值、业务表现、质量、成本、风险**持续达标**，并决定迭代优先级。

### 要回答的问题
1. 核心指标与护栏现在怎么样？与阈值差多少？
2. 哪些分群表现异常？
3. 迭代优先级怎么排——按用户影响 × 证据强度，还是按声音大小？
4. 什么时候该继续投、该优化、该缩减、该回滚？

### 关键问题
> **护栏现在离红线还有多远，这个距离在往哪个方向变？**
> 只看当前值会漏掉"正在滑向红线"的趋势。

### 方法论
行为/留存/转化监测、故障监控、支持反馈聚类、成本与分群表现分析；周期性复盘。

### 判断标准
| 判据 | 达标线 |
|---|---|
| 指标达标 | 核心指标与护栏均与阈值对比，含趋势 |
| 质量 | 故障率、响应时延、缺陷密度在阈值内 |
| 成本 | 单位经济性有实测值，非估算 |
| 分群 | 关键分群单独看，不靠总体掩盖 |
| 优先级 | 迭代项按"用户影响 × 证据强度"排序 |
| 决策 | 继续优化 / 扩大 / 缩减 / 暂停 / 回滚 五选一 + 依据 |

### 工作内容
1. 定期巡检：核心指标 + 护栏 + 质量 + 成本 + 分群，输出结论而非数字堆。
2. 聚类支持反馈与工单，找出高频未解决问题。
3. 排迭代优先级，标注每项背后的证据等级。
4. 对接近红线的项做前瞻处置（提前降级/限流，而不是等触线）。
5. 出继续/扩大/缩减/暂停/回滚决策。
6. **每月做一次决策校准**：对账本阶段及上游阶段的预测，看命中率与过度自信曲线。
   某个阶段连续 2 次 `miss` → 检查该阶段判断标准是否太松，**当场改流程**
   （见 `calibration.md` 第 5 节）。改动要写进 `assets/lessons.md` 并注明生效日期。
7. **AI 产品**：每次模型/prompt/检索变更后跑一次回归门禁并归档报告；
   监控输入分布漂移、逐切片通过率趋势、人工升级率、单位成本。

### AI 专项工作（仅 AI 产品适用）

**要回答的问题**
1. 线上 badcase 怎么被捕获——自动抽检还是等用户投诉？
2. 输入分布漂移了吗？逐切片通过率趋势如何？
3. 每次成功成本与 P95 延迟的时间序列是什么形状？
4. 线上问题怎么回流进评测集？
5. 模型/Prompt 变更后，谁保证重新过了门禁？

**关键问题**
> **用户已经不再用的那个功能，监测面板还在显示"绿色"吗？**

**方法论**
badcase 监控（自动抽检 + 反馈回流）＋质量漂移监控（输入分布 + 逐切片趋势）
＋成本延迟趋势 ＋回归集回流 ＋变更重新过门禁。

**判断标准**
| 判据 | 达标线 |
|---|---|
| badcase 捕获 | 自动抽检 + 用户反馈两条通道 |
| 漂移监控 | 输入分布分桶比对 + 逐切片通过率趋势 |
| 成本趋势 | 每次成功成本 + P95 的时间序列，不只是当前值 |
| 回流 | 每条事故落一条回归集，带 trace_id 与根因 |
| 变更门禁 | 模型/Prompt 变更自动触发全量评测 |

**工具**
`$PM/moh/skills/monitoring-setup-guide/SKILL.md` ·
`$PM/moh/skills/incident-postmortem/SKILL.md` ·
`references/ai-evals.md` §6（生命周期与责任人）

**工作内容**
1. 在监测计划里加 AI 漂移看板（分布漂移 / 逐切片趋势 / 升级率 / 单位成本）。
2. 建 badcase 捕获通道（自动抽检 + 反馈入口），并定回流规则。
3. 给漂移阈值绑定动作（触发重测 / 补样本 / 排查 / 降级）。
4. 每次 AI 配置变更后跑全量评测并归档报告。
5. 每月做一次决策校准；某阶段连续 2 次 miss → 当场改该阶段的证据要求。

**原始材料与来源**
试点期与上线后的 AI 指标、回归集回流条目、事故复盘记录。

**优先证据**
- **E1**：线上真实通过率趋势、成本时间序列、badcase 计数
- **E4**：一线值班与客服的 badcase 反馈

**产物**
- AI 漂移监控配置（并入监测计划）
- badcase 回流机制与回归集增量
- 每次变更的回归报告

**质量标准**
- 漂移阈值写死数值 + 触发动作，不写"关注"。
- 每条事故必须落一条回归集，否则评估集三个月后就过期。
- 趋势与当前值同时呈现。

**门控补充条件**
- 无质量漂移监控 → 本阶段不得 GO。
- 变更后未重新过门禁 → 不得 GO。

### 决策门控
- **通过 GO** → 阶段 18 规模化与生命周期管理。
- **有条件通过 CONDITIONAL** → 局部问题 → 分群调整 + 限定范围。
- **返工 REVISE** → 持续不达标但方向仍可能成立 → 缩减范围 + 补验证。
- **终止 STOP** → 持续不达标/护栏反复触发 → 暂停或回滚。
