### 适合场景
方向与策略已定；需要把"给用户价值"翻译成可观测指标。

### 目标
定义核心结果指标、护栏指标、基线、目标阈值与观察周期。

### 要回答的问题
1. 什么结果代表**用户**获得价值？什么代表**业务**获得价值？
2. 我们**不能牺牲什么**（护栏）？——质量、成本、合规、信任，任选其一。
3. 现在的基线是多少？目标阈值定多少？多久看一次？
4. 指标怎么分群看（按角色/场景/新老用户）？

### 关键问题
> **如果这个指标涨了但用户体验其实更差了，我们的护栏能拦住发布吗？**
> 答不上来 = 没有护栏，不许进入下一阶段。

### 方法论
指标树（北极星 → 一级驱动 → 行为指标）、历史数据检查、分群设计。
北极星只选 1 个；健康指标 3 个左右，覆盖价值、质量、成本三面。

### 判断标准
| 判据 | 达标线 |
|---|---|
| 可测性 | 每个指标有分子/分母/口径/时间窗 |
| 基线 | 有历史数据基线或明确标注"无基线，需先采" |
| 阈值 | 目标阈值 + 观察周期写死，不是"提升" |
| 护栏 | ≥ 1 条护栏，且有明确的失败含义 |
| 可决策性 | 指标波动能直接导致某个动作（放量/回滚/暂停） |
| 分群 | 说明要看哪几个分群，事后不靠临时解释 |

### 工作内容
1. 建指标树：1 个北极星 + ≤3 个健康指标 + 每层的行为驱动。
2. 为每个指标写口径卡（分子/分母/人群/时间窗/数据源/当前基线）。
3. 写护栏：至少一条质量或成本护栏，标注"触线即停止放量"。
4. 设阈值与观察周期（试点期多长、看几次）。
5. 检查每个指标背后对应哪个决策动作。

### 原始材料与来源
历史埋点与行为数据、现有看板、留存与 churn 数据、销售与运营的商业指标、财务口径。

### 优先证据
- **E1**：历史真实数据（基线必须来自实际，不是估计）
- **E3**：行业/竞品公开基准值（用于合理性对照，不用于定义目标）
- **E5**：北极星模板类框架

### 产物
- 指标树（1 北极星 + 3 健康指标）
- 指标口径卡（含基线、阈值、周期、数据源）
- 护栏清单与触发动作

### 质量标准
- 每个指标能被一句 SQL/一个看板复现，口径无歧义。
- "提升用户体验"这种不可测的表述一律不写。
- 护栏写明触发后做什么，不是"关注"。
- 基线缺失时明确标"需先采基线"，并把它变成一个前置任务。

### AI 专项工作（仅 AI 产品适用）

**要回答的问题**
1. "任务成功"对 AI 功能具体指什么——端到端任务完成，还是输出看起来对？
2. 有哪几类失败模式？每一类的容忍度是多少？
3. 哪些分群被服务得更差？（平均值会掩盖这个）
4. 质量阈值、成本上限、延迟上限分别是多少，用 CI 下界还是点估计？

**关键问题**
> **如果这个指标涨了但有一类用户被服务得更差了，护栏拦得住吗？**

**方法论**
任务级指标 → 失败模式清单（幻觉/过度自信/拒答/格式漂移/越权/注入/隐私串号/延迟超时/成本超限）
→ 分群质量表 → 阈值用 CI 下界（`evidence_stats.py wilson`）。

**判断标准**
| 判据 | 达标线 |
|---|---|
| 任务指标 | 端到端任务完成度，不只有模型侧指标 |
| 失败类型 | ≥5 类，每类给容忍度（安全类容忍度 0） |
| 分群 | 说明看哪几个分群，事后不靠临时解释 |
| 阈值 | 目标值 + 样本量 + CI 下界，不用点估计 |
| 成本延迟 | 每次成功成本上限 + P95 延迟上限 + 超限动作 |

**工具**
`$PM/moh/skills/metrics-framework/SKILL.md` ·
`$PM/phuryn/pm-marketing-growth/skills/north-star-metric/SKILL.md` ·
`xlsx` skill 做阈值表

**工作内容**
1. 在指标树里给 AI 功能建任务级指标（不是只加一个"满意度"）。
2. 写失败模式清单 + 每类容忍度（安全/合规类 = 0）。
3. 写分群质量表：哪个分群的通过率更低。
4. 写质量阈值（目标值 + 样本量 + CI 下界）、成本上限、延迟上限。

**原始材料与来源**
阶段 6 的 AI 能力边界、阶段 4 的单位经济模型、历史故障与投诉分类。

**优先证据**
- **E1**：线上真实通过率与失败模式分布（若有）
- **E3**：行业公开基准值（仅作合理性对照）

**产物**
- AI 任务级指标卡与失败类型清单（并入指标树）
- 成本与延迟上限（并入护栏清单）

**质量标准**
- 每个失败模式都有专属指标，不能只报一个总体通过率。
- 阈值一律带 CI 下界；n 不够就明写"探索性，无统计功效承诺"。
- 成本上限写"超限怎么办"，不是"关注成本"。

**门控补充条件**
- 只报总体平均通过率、未做分群 → 本阶段不得为 GO。

### 决策门控
- **通过 GO** → 阶段 8 制定验证计划。
- **有条件通过 CONDITIONAL** → 指标可测但缺基线/埋点 → 先补数据能力（有条件通过）。
- **返工 REVISE** → 指标不可测或不可解释 → 重审目标/改指标。
- **终止 STOP** → 目标本身不可衡量且无替代口径 → 回阶段 6。
