### 适合场景
方案已选定；开发排期前判断"能不能做、做到什么程度"。

### 目标
给出可行性判断、核心风险清单、**可执行的发布红线**、最小可交付范围与依赖。

### 要回答的问题
1. 技术上做得到吗？数据够吗？成本能承受吗？运营与支持能跟上吗？
2. 依赖了哪些外部系统/供应商/团队？它们的风险是什么？
3. 最小可交付范围（MVD）是什么——砍到哪一刀还仍然验证核心假设？
4. 哪些风险必须现在就解决？哪些可以监控？

### 关键问题
> **如果把范围砍到最小，这个版本还能证伪核心价值假设吗？**
> 不能 → 范围划错了，这不是一个"小版本"，它测不到任何东西。

### 方法论
DUFV（Desirability/Usability/Feasibility/Viability）+ PESTEL 风险扫描；
act-now / start-track 二分（**强制约 40/60 分**，全部 act 等于没有优先级）；
技术 spike 验证高风险依赖。

### 判断标准
| 判据 | 达标线 |
|---|---|
| 可行性证据 | 高风险项有 spike/测试结论，非"应该没问题" |
| 风险分级 | 每条风险有 act-now / watch 标签 + 责任人 + 缓解动作 |
| 发布红线 | ≥ 1 条，写全触发条件/监测方式/负责人/处置动作 |
| MVD 原则 | 明确写出砍掉什么、保留什么、为什么保留 |
| 依赖清单 | 每条外部依赖有失效时的应对（替代方案或降级） |
| 成本 | 至少给出单位成本量级或上限区间 |

### 工作内容
1. 扫 DUFV + PESTEL 十维风险扫描，输出清单。
2. 二分 act-now / watch（强制 40/60），act-now 每条配"谁做什么、怎么知道已解决"。
3. 定义 MVD：写下"这个版本不做什么"和"它仍要能证明什么"。
4. 写发布红线（触发条件 / 监测方式 / 负责人 / 处置动作，四项齐全）。
5. 列依赖与依赖失效预案。

### 原始材料与来源
技术方案与架构、spike 结论、历史事故复盘、供应商 SLA 与报价、监控现状、合规要求、成本模型。

### 优先证据
- **E1**：历史真实负载、真实故障率、真实单位成本
- **E3**：供应商公开 SLA/定价、竞品实际架构公开信息
- **E5**：通用风险清单模板

### 产物
- 风险登记表（含 act-now/watch 分级、责任人与缓解动作）
- MVD 范围定义
- 发布红线（可执行格式）
- 依赖清单 + 失效预案

### 质量标准
- 每条风险都带责任人姓名与"何时做"，不是"注意"。
- act-now 占比强制在 30–50% 之间，超了说明没做分级。
- 红线写成"若 X（可观测）则 Y（动作），由 Z 负责，在 T 周期看"的可执行句。
- 依赖失效时至少有一条降级路径。

### AI 专项工作（仅 AI 产品适用）

**要回答的问题**
1. 训练/检索/评估数据能不能合法用？可留存范围是什么？
2. 模型供应与部署有什么约束——限流、区域、SLA、版本漂移？
3. Agent 能调用哪些工具？写权限多大？调用留不留痕？
4. AI 失败时谁来接管？接管率多少、人工负荷多大、多久接管？
5. 模型挂了/成本爆了/合规不允许时怎么办？
6. 运行成本模型长什么样？规模不经济的拐点在哪？

**关键问题**
> **如果供应商明天涨价 50% 或下线这个模型，这个产品还成立吗？**

**方法论**
AI 特有的 DUFV+PESTEL 扫描：数据权限与授权 → 供应与部署约束 → 工具权限与审计
→ 人工接管机制 → 降级方案 → 运行成本模型。

**判断标准**
| 判据 | 达标线 |
|---|---|
| 数据权限 | 来源、授权、可留存范围逐项清楚 |
| 供应约束 | 限流/区域/SLA/版本漂移有对策，替换成本已知 |
| 工具权限 | 最小权限 + 写操作需确认 + 调用留痕 |
| 人工接管 | 触发条件 + 接管率 + 人工负荷 + SLA |
| 降级 | 模型不可用/超预算/违规时各有路径 |
| 成本 | 每次成功成本 + 固定成本 + 规模不经济拐点 |

**工作内容**

**优先证据**
- **E1**：真实峰值负载下的成本与延迟、真实接管率
- **E3**：供应商公开 SLA/定价/区域限制

**产物**
- AI 专项风险登记（并入风险登记表）
- 运行成本模型（并入单位经济表）
- 人工接管机制与降级路径

**质量标准**
- 工具权限写最小权限集，写操作必须有确认环节。
- 成本模型标明哪些是实测、哪些是外推。
- 降级方案具体到"触发什么 → 谁 → 做什么"。

**门控补充条件**
- **写不出降级方案 → 阶段 10 风险评估不合格，本阶段不得为 GO。**
- 数据授权不清 → 阶段 11 不得进入开发。

### 决策门控
- **通过 GO** → 阶段 11 PRD 与执行计划。
- **有条件通过 CONDITIONAL** → 有需先验证的约束 → 排 spike，闭环后放行。
- **返工 REVISE** → MVD 切不到能验证假设 → 回阶段 9/6 重划范围。
- **终止 STOP** → 存在不可接受风险且无缓解方案 → 终止并记录。
