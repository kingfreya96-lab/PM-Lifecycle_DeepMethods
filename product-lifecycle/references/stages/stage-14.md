### 适合场景
上线准备通过；需要在真实但受控的场景里检验是否真的解决了问题。

### 目标
在真实使用中验证核心假设，同时把风险限制在可承受范围内。

### 要回答的问题
1. 在真实但受控的场景里，产品是否真的解决了已验证的问题？
2. 风险是否可控（护栏未触发）？
3. 试点要扩大到什么范围、观察多久，才能做出有把握的判断？

### 关键问题
> **这次试点的结果，能区分"假设成立"和"样本不够"吗？**
> 不能 → 试点设计失败，先修设计再跑，不要用跑出来的数据硬下结论。

### 方法论
定义目标人群、范围、期限、观察指标、护栏、停止条件；**阈值预先写明**（pre-registration）。
试点范围从最小开始，逐级放量（内部 → 单租户 → 单分群 → 部分流量）。

### 判断标准
| 判据 | 达标线 |
|---|---|
| 预注册 | 指标阈值、周期、停止条件在试点开始**前**写死 |
| 样本匹配 | 样本量/周期足以区分成功与证据不足（依据阶段 8） |
| 护栏监控 | 护栏有实时/高频监测，不是事后回看 |
| 对照 | 条件允许时有对照（历史同期、分群对照） |
| 停止条件 | 写明触发即停的具体数值与执行人 |
| 范围受控 | 明确哪些用户不在试点内及其原因 |

### AI 专项工作（仅 AI 产品适用）

**要回答的问题**
1. 在受控范围里，真实任务效果如何——完成率是多少？
2. AI 输出被直接采用、被改写、还是被弃用？比例多少？
3. 人工改写率/接管率是多少（这是人工负荷，也是质量早期信号）？
4. 有没有异常与滥用——对抗输入、批量滥用、成本攻击？
5. 试点期实测的单位成功成本是多少？

**关键问题**
> **如果人工改写率是 60%，这个功能省的是时间还是制造了返工？**

**方法论**
真实任务试点（不用合成数据）＋采纳/改写/弃用三分类 ＋人工负荷测量
＋异常与滥用观察 ＋单位成功成本实测。

**判断标准**
| 判据 | 达标线 |
|---|---|
| 真实任务 | 真实用户真实任务，完成率有分母 |
| 采纳率 | 采用/改写/弃用三分类有比例 |
| 人工负荷 | 改写率、接管率、接管 SLA |
| 异常滥用 | 对抗输入、批量滥用、成本攻击有观察记录 |
| 成本 | 单位成功成本实测值 + 上限 |

**工具**
`references/ai-evals.md` §4.3（badcase 回流）·
`$PM/moh/skills/experiment-designer/SKILL.md`

**工作内容**
1. 在试点章程里加 AI 专项指标（任务效果、采纳率、人工改写率、单位成功成本）。
2. 埋点能区分"采用/改写/弃用"三种结果。
3. 每日巡检人工改写率——升上去就是质量下降信号。
4. 记录异常与滥用事件（对抗输入、批量滥用、成本攻击）。
5. 每条线上事故/badcase 落一条回归集（带 trace_id 与根因分类）。

**原始材料与来源**

**门控补充条件**

### 决策门控
- **通过 GO** → 阶段 15 分析验证结果（注意：GO 只代表"数据可分析"，不代表结论）。
- **有条件通过 CONDITIONAL** → 证据不足 → 补试点（延长周期/扩样本/修设计）。
- **返工 REVISE** → 护栏触发或关键假设失败 → 暂停、调整后重试。
- **终止 STOP** → 不可接受风险 → 立即停止并回滚。
