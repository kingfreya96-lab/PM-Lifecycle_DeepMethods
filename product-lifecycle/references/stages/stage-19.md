### 适合场景
产品进入稳定期，需要决定"继续维护 / 迁移 / 退场"；或维护成本已超价值。

### 目标
基于使用趋势、成本、依赖与替代方案，做出**继续维护 / 迁移 / 逐步退场 / 停止服务**的决策，
并把用户影响、数据处理与支持安排落到可执行。

### 要回答的问题
1. 还有多少人在用？用量趋势如何？维护成本占价值多少？
2. 用户有多深的依赖（数据、流程、集成）？
3. 有没有更好的替代方案（含竞品与自建）？
4. 若迁移/退场：用户影响怎么减？数据怎么交接？支持怎么过渡？
5. 执行条件是什么——谁在什么时间点做到什么才停？

### 关键问题
> **如果今天下线，谁会最先痛、最晚知道？**
> 退场方案里必须有通知、支持、迁移、缓冲期四件事，缺一件就会变成事故。

### 方法论
EOL go/no-go 评估、生命周期打法选择（extension / replacement / retirement）、
EOL 分阶段清单、干系人沟通排序、用户公告与 FAQ。

### 判断标准
| 判据 | 达标线 |
|---|---|
| 使用趋势 | 有用量与趋势数据（非感觉） |
| 维护成本 | 有实测成本与频率 |
| 依赖深度 | 识别出重度依赖用户/集成 |
| 替代方案 | 列出可迁移目标与差异说明 |
| 执行条件 | 每个阶段有"做到什么才能进入下一阶段" |
| 用户保护 | 通知提前期、迁移路径、数据导出、支持过渡齐备 |
| 决策 | 4 选 1（继续维护/迁移/逐步退场/停止服务）+ 条件 |

### 工作内容
1. 评估 go/no-go：用量、成本、依赖、替代方案四维打分。
2. 选择打法：延长维护 / 替换迁移 / 逐步退场 / 立即停止。
3. 若是迁移或退场：写分阶段执行计划（阶段 → 完成条件 → 时间点 → 负责人）。
4. 产出用户侧材料：公告、FAQ、迁移指南、数据导出说明。
5. 干系人沟通排序：谁先、谁后、谁需要单独谈。
6. 定再启条件（什么情况下重新考虑）。
7. **归档前的两件事**（见 `methodology-ledger.md`）：
   - **预测全量对账**：本项目所有预测逐条打分，含因项目取消而无法判定的（标 `void`）。
   - **方法论提炼**：读全部 `lessons.md` 条目 → 合并同类项 → 标出重复出现 ≥2 次的升为 `patterns.md`
     → 能变成机器可判检查项的写进 `scripts/gate_check.py` **并加一条回归测试**。
   **这两件事没做完 → 阶段 19 的门控不能是 GO**（见 `methodology-ledger.md` 第 6 节）。

### AI 专项工作（仅 AI 产品适用）

**要回答的问题**
1. 供应商或模型版本变化会怎样——涨价、下线、能力回退、合规口径变化？
2. 知识更新谁来做、成本多少（模型不更新知识，靠管道更新）？
3. 单价变化怎么打到单位经济上？
4. 用户是否依赖 AI 特有行为（迁移到替代方案会怎样）？
5. 什么条件下关掉 AI 能力，或换成非 AI 方案？

**关键问题**
> **如果这个模型明天必须下线，替代方案是什么、多久能切完、用户会失去什么？**

**方法论**
AI 依赖盘点（模型/评估集/数据/提示词/工作流）→ 变更情景推演（涨价/下线/回退）
→ 知识更新成本 → 迁移影响 → 关闭或切换判据。

**判断标准**
| 判据 | 达标线 |
|---|---|
| 供应变化 | 涨价/下线/回退三种情景各有对策 |
| 知识更新 | 更新管道与责任人 + 成本量级 |
| 成本影响 | 单价变化对单位经济的量化影响 |
| 迁移影响 | 用户依赖点 + 替代路径 + 切换时长 |
| 关闭判据 | 什么条件下关 AI / 换非 AI 方案 |

**工具**
`$PM/moh/skills/product-health-analysis/SKILL.md` ·
`$PM/phuryn/pm-ai-shipping/skills/intended-vs-implemented/SKILL.md` ·
`references/methodology-ledger.md`

**工作内容**
1. 盘点 AI 依赖资产（模型、评估集、数据、提示词、编排）。
2. 推演三种供应变化情景，写出各自对策与切换时长。
3. 算知识更新成本与责任归属。
4. 量化单价变化对单位经济的影响。
5. 写关闭/切换判据：什么条件下执行、执行后用户怎么走。

**原始材料与来源**
阶段 17 的漂移与成本趋势、阶段 18 的容量模型、供应商合同与变更条款。

**优先证据**
- **E1**：真实单位成本与用量趋势
- **E3**：供应商公开的版本/价格/弃用政策

**产物**
- AI 依赖盘点与变更情景表（并入 EOL 评估）
- 关闭或切换判据

**质量标准**
- 关闭判据要可执行（"单位成本连续 3 个月 > X 且非 AI 方案达标"），不写"必要时关闭"。
- 数据保留与导出策略明确（含合规保留期）。
- 迁移影响要说到用户侧损失，不只说技术工作量。

**门控补充条件**
- 写不出关闭或切换判据 → 本阶段不得 GO（AI 能力没有退路就不是可维护资产）。

### 决策门控
- **通过 GO** → 继续维护 / 执行选定打法，进入下一轮阶段 17 监测。
- **有条件通过 CONDITIONAL** → 先补条件（用量回升、外部依赖变化）→ 定期复查。
- **返工 REVISE** → 数据不足以判断 → 继续监测一个周期。
- **终止 STOP** → 执行退场/停止服务，全部条件满足才执行。
