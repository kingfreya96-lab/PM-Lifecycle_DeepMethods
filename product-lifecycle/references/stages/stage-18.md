### 适合场景
发布后运行稳定，准备扩大覆盖或提升容量。

### 目标
确认**扩大后**价值、质量、成本、支持能力、风险是否仍可接受。

### 要回答的问题
1. 规模上去之后，单位经济性变好还是变差？
2. 支持与运营能力跟得上吗（人、流程、工具）？
3. 容量与成本计划是什么？瓶颈在哪？
4. 什么条件下继续扩大，什么条件下限制？

### 关键问题
> **规模翻十倍时，是成本摊薄了还是风险放大了？**
> 很多产品在 100 用户时健康，10000 用户时单位成本翻倍。

### 方法论
容量规划与压测、单位经济性建模（随规模变化）、支持能力评估、维护责任分配、持续监测标准升级。

### 判断标准
| 判据 | 达标线 |
|---|---|
| 价值保持 | 扩量后留存/转化不显著劣化 |
| 质量保持 | 故障率、时延、缺陷率在阈值内且有容量余量 |
| 成本可预测 | 有随规模的成本模型与瓶颈识别 |
| 支持能力 | 人力与流程能承接预期量 |
| 扩大条件 | 写明"满足什么条件才能继续扩" |
| 维护责任 | 有明确的责任人与维护标准 |

### 工作内容
1. 建模：用户量 → 成本结构 → 单位经济性，标出规模不经济点。
2. 压测与容量余量评估，标出下一个瓶颈。
3. 支持能力评估（人力、响应 SLA、工具缺口）。
4. 定维护责任与持续监测标准（比试点期更严）。
5. 出扩大条件与限制扩大条件。

### 原始材料与来源
运行期真实成本与容量数据、压测结果、支持工单量与 SLA、单位经济性实测、运维与财务口径。

### 优先证据
- **E1**：真实负载、真实成本、真实工单量
- **E3**：同类规模化产品的公开成本结构（对照）
- **E5**：容量估算模型

### 产物
- 规模化容量与成本模型（含瓶颈与余量）
- 支持能力评估
- 维护责任与监测标准
- 扩大 / 限制扩大的条件清单

### 质量标准
- 成本模型标明哪些是实测、哪些是外推。
- 写明规模不经济的拐点。
- 扩大条件是**可观测的**（如"单位成本 < X 且 故障率 < Y"）。

### AI 专项工作（仅 AI 产品适用）

**要回答的问题**
1. 规模上去了，每次成功成本还成立吗？长尾请求更贵，拐点在哪？
2. 流量结构变化会不会拉低质量（新手更多、边缘场景更多）？
3. 供应商容量够吗——配额、限流、区域供给？
4. 模型、评估集、数据集各由谁维护？

**关键问题**
> **从 1 万用户到 100 万用户，最先崩的是质量、成本，还是供应商配额？**

**方法论**
规模模型（用户量 → 请求量 → 成本结构 → 拐点）＋质量保持性验证
＋供应商容量预案 ＋AI 资产维护责任矩阵。

**判断标准**
| 判据 | 达标线 |
|---|---|
| 单位成本 | 规模曲线 + 规模不经济拐点 |
| 质量保持 | 规模后分群通过率不下降的证据 |
| 容量 | 配额/限流/区域供给有预案 |
| 维护责任 | 模型/评估集/数据集各有人 |

**工具**
`$PM/moh/skills/capacity-planning/SKILL.md` ·
`$PM/moh/skills/load-testing-plan/SKILL.md` ·
`references/domain-standards.md` §1（单位经济）

**工作内容**
1. 把 AI 成本并进规模模型：请求量 × 每次成功成本 = 月度成本，画出拐点。
2. 验证质量保持：规模后分群通过率、失败模式分布是否恶化。
3. 写供应商容量预案（配额、限流、多供应商或降级）。
4. 建 AI 资产维护责任矩阵。

**原始材料与来源**
阶段 17 的成本与质量趋势、阶段 18 的容量评估、供应商配额与商务条款。

**优先证据**
- **E1**：真实增长曲线下的成本与质量实测
- **E3**：供应商公开配额与定价

**产物**
- AI 规模成本与容量模型（并入规模化模型）
- AI 资产维护责任矩阵

**质量标准**
- 成本模型标明实测与外推。
- 扩大条件可观测（单位成本 < X 且通过率 ≥ Y），不写"情况允许时扩大"。
- 维护责任写到人，不写"团队"。

**门控补充条件**
- 单位成本或质量随规模恶化 → 先优化再扩，不扩。

### 决策门控
- **通过 GO** → 维持并持续扩大（进入阶段 19 判断维护/迁移/退场）。
- **有条件通过 CONDITIONAL** → 经济性/质量接近临界 → 限制扩展并改进。
- **返工 REVISE** → 单位成本或质量恶化 → 优化后再扩。
- **终止 STOP** → 规模化不可行 → 收缩到当前规模并重新评估（见阶段 19）。
