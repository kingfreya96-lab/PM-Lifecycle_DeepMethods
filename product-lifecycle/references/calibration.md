# 决策校准回路 — 让判断力可积累

**这是当前 skill 最大的缺口。** 现有流程产出 20 张阶段记录卡，然后结束。
阶段 15 验证的是"试点结果对不对"，从没人回头验证**"当初那个判断对不对"**。

没有回路，skill 只是一次性流程；有了回路，每跑一轮，判断力就校准一点。

---

## 1. 什么是决策校准

每次门控裁决（GO / CONDITIONAL / STOP）本质上是一次**预测**：
"我认为这个方向值得投入 / 不值得投入 / 证据还不够"。

校准 = 事后拿真实结果对账，算出：
- **命中率**：说"值得做"的项目里，事后真的做成的比例
- **过度自信度**：说"90% 有把握"的项目，实际只有多少成立
- **系统性偏差**：是不是总在同一个地方错（高估市场规模？低估技术难度？）

目标不是"永远判断对"，是**知道自己在哪类判断上不可靠**，从而在那些地方强制要 E1。

---

## 2. 预测日志（Prediction Log）

每次门控裁决时，在 `decisions/predictions.jsonl` 追加一条：

```json
{
  "id": "P-2026-10-24-001",
  "date": "2026-10-24",
  "stage": 5,
  "product": "AI 客服回复起草",
  "claim": "电商客服在旺季存在真实的回复产出瓶颈，且该瓶颈值得用 AI 起草解决",
  "verdict": "CONDITIONAL",
  "confidence": 60,
  "falsifier": "试点中 AI 草稿采纳率连续两周 < 20%，或 AS-2 显示重复问答占比 > 70%",
  "check_by": "2026-11-21",
  "outcome": null,
  "outcome_note": "",
  "scored": false
}
```

字段说明：
- **claim**：一句话，可证伪。不是"这个方向不错"。
- **confidence**：0–100 的**事前**置信度。禁止事后改数字（要改就新开一条并注明）。
- **falsifier**：反证条件，与记录卡的「反证条件」一致（见 `evidence-discipline.md` 第 5 节）。
- **check_by**：什么时候回来对账。到期未对账 = 这条预测作废，也要计入统计。
- **outcome**：`hit` / `miss` / `partial` / `void`（作废）。

**规则**：
- 预测在**裁决当场**写，不许事后补。
- **只对有反证条件的裁决记预测**。没有 falsifier 的判断不可校准，不记。
- STOP 也要记 —— "我们及时停掉的判断"同样有信息量。

---

## 3. 对账（Scoring）

到 `check_by` 之后，拿到真实结果，回填 `outcome`：

| outcome | 含义 |
|---|---|
| `hit` | 反证条件未触发，且方向被证实 |
| `miss` | 反证条件触发了 |
| `partial` | 部分成立（要写 `outcome_note` 说明哪部分） |
| `void` | 因外部原因（项目取消、公司战略变更）无法判定 —— **单独统计，不进命中率分子分母** |

**打分必须基于事先写下的 falsifier，不是基于结果感觉。**
如果结果是"看起来不错"，但 falsifier 没触发、也没证据显示成立 → `partial`，不是 `hit`。

对账时写一行 `outcome_note`：这次判断**靠什么证据**做对的/做错的。
这一行才是校准的真正价值来源。

---

## 4. 校准报告

`scripts/calibrate.py` 读取预测日志 + 结果，输出：

1. **总体命中率**：hit / (hit + miss + partial)。partial 按 0.5 计并单独报出。
2. **过度自信曲线**：按事前置信度分桶（0-30 / 31-50 / 51-70 / 71-85 / 86-100），
   每桶的「平均预测置信度」vs「实际命中率」。**预测 70% 的那批实际只中 40% → 过度自信 30pp**。
3. **系统性偏差**：同一类判断连续错 2 次 → 标记出来。
   例如连续 3 次高估市场规模 → 阶段 4 的裁决**强制**要求 E1 行为数据或付费意愿实测。
4. **未对账清单**：`check_by` 已过但 `outcome` 仍为 null 的预测。
   这些会稀释统计，必须补对账或标 `void`。
5. **改进建议**：哪一阶段的预测准确率最低 → 那个阶段的方法论需要补。

**校准报告是阶段 19 归档的一部分，也是下一轮改进的输入。**

---

## 5. 怎么用校准结果改流程（闭环）

校准不是发个报告就完事。要**真的改 skill**：

1. 某阶段连续 2 次 `miss` → 检查该阶段的判断标准是否太松 → **改 `references/stages/stage-NN.md`**。
2. 某阶段过度自信严重 → 该阶段门控**提高证据要求**（比如阶段 4 从"E1 或 E2"改成"必须 E1"）。
3. 某类反证条件从未触发过 → 可能写得不可观测 → 改写成可测的数值。
4. 某个 falsifier 触发后团队没执行处置动作 → 说明红线是假的 → 修红线。

**这些改动要写进 `lessons.md`，并注明生效日期。** 下次跑 skill 时读它。

---

## 6. 品味（taste）的度量

品味不是"我觉得好不好"，是可校准的。对产品方案的判断也可以进预测日志：

```json
{
  "id": "T-2026-10-24-001",
  "date": "2026-10-24",
  "stage": 9,
  "product": "AI 客服回复起草",
  "claim": "方案 A（草稿+一键改写）的交互优于方案 B（纯话术库检索）",
  "verdict": "GO",
  "confidence": 55,
  "falsifier": "在 5 人任务测试中，方案 B 的完成率不低于方案 A 且主观评分显著更高",
  "check_by": "2026-10-31",
  "outcome": null
}
```

**品味判断的 falsifier 必须是可测的**：完成率、任务时长、错误率、盲评排序，
而不是"用户更喜欢 A"（那是主观证据，不是可证伪的）。

**多轮迭代后的品味曲线**：同一产品的方案迭代 5 版后，回看 T-记录 ——
如果第 5 版的预测准确率明显高于第 1 版，说明判断力在长；
如果持平，说明方法没有改进，需要换方法而不是加练习。
