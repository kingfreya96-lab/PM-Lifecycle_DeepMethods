# Product Artifacts — 产物生成

**这个 skill 只做一件事：把前序阶段的真实内容，变成当前阶段的真实产物。**

不是填空。不是给模板。是读上下文 → 写出一份团队能直接用、能改、能据此开工的东西。

## 何时用

- 某个阶段的门控已通过，需要产出该阶段的交付物
- 前序产物已存在，需要据此生成下一份（如：指标树 → 验证计划 → PRD）
- 需要给团队一份可编辑的 HTML 展示页
- 需要刷新项目进度跟进表

## 不适用

- 还在判断"要不要做" → 用 `product-lifecycle` 走门控
- 不知道用哪个 PM 方法 → 用 `pm-meta` 搜
- 只需要一份孤立文档、没有前序上下文 → 直接写，不必走本 skill

## 执行流程

按顺序做，不要跳步：

1. **读前序产物**。扫 `stages/*/artifacts/` 下所有 `.md` / `.json` / `.csv`。
   缺什么就记下来，不要凭空补。缺失项直接写进产物的"待补"栏。
2. **确认生成目标**。从下表的"阶段"列找到当前阶段对应的产物。
3. **按"生成指令"写**。指令里的每一句话都是要求，不是建议。
4. **过"质量标准"**。任一条不满足 → 回去补，不要交付。
5. **生成 HTML**。`python3 ~/.codex/skills/product-lifecycle/scripts/stage_dashboard.py build <工作区> <阶段>`
   （需安装 product-lifecycle skill，其 scripts/ 才有此文件）
6. **同步**。HTML 里改过的内容必须写回 Markdown，Markdown 是唯一真源。

## 生成硬规则

这五条违反任何一条，产物就是废的：

1. **不许留空表格**。写不出就写"证据不足 + 缺什么 + 谁能补 + 期限"。
2. **每个数字必须有来源**。来源可以是前序产物、访谈记录、公开数据。写不出来源 → 标 `[未验证]`。
3. **必须引用前序产物**。PRD 里的每个功能，要能追到方案对比表的某一项；指标树里的每个指标，要能追到问题陈述。
4. **区分事实与判断**。观察到的事实、推断、建议分开写，不要混成一段。
5. **可证伪**。任何结论后面跟一句"什么情况下这个结论是错的"。

## 产物清单

### D1 发现与验证（阶段 1-4）

| 产物 | 阶段 | 输入 | 生成指令 | 质量标准 |
|---|---|---|---|---|
| 数据盘点表 | 1 | PRODUCT.md + 可用数据源 | 列出所有可用数据源：类型、口径、样本量、更新频率、已知偏差 | 每行有源名+类型+口径+样本量+限制；无源的维度明确标"无数据" |
| 候选问题清单 | 1 | 信号表 | 聚类成 3-5 条可证伪的问题陈述 | 每条含角色+情境+后果；不含功能名 |
| 市场机会评估 | 4 | 候选问题 + 竞品数据 + 访谈 | TAM/SAM/SOM + 竞品格局 + 致命假设清单 | 每个数字有来源；致命假设有证伪条件 |
| 单位经济表 | 4 | 定价假设 + 成本结构 | CAC/LTV/回本周期/毛利率，乐观/基准/悲观三场景 | 三场景齐全；每个假设标注来源 |

### D2 方向与策略（阶段 5-8）

| 产物 | 阶段 | 输入 | 生成指令 | 质量标准 |
|---|---|---|---|---|
| 方向决策备忘 | 5 | 市场机会 + 单位经济 | ≥2 个方向对比，必须含"什么都不做" | 至少 2 个候选；有参照物；写明放弃理由 |
| 产品策略文档 | 6 | 方向决策 + 用户画像 | 目标用户 + 价值主张 + 不做什么 + 成功指标 + 风险 | "不做什么"≥3 条且具体 |
| 指标树 | 7 | 策略 + 用户旅程 | 北极星→驱动指标→输入指标 | 每个指标有名称+定义+基线+CI 下界+数据源 |
| 验证计划 | 8 | 指标树 + 假设清单 | 每个假设→验证方法+样本量+时间+成本 | 每个假设有 falsifier 和判定阈值 |

### D3 方案与交付（阶段 9-13）

| 产物 | 阶段 | 输入 | 生成指令 | 质量标准 |
|---|---|---|---|---|
| 方案对比表 | 9 | 验证计划 + 竞品分析 | ≥2 个方案 × 多维度对比矩阵 | 有参照物（已上线产品）；每格有评分+依据 |
| 可行性评估 | 10 | 方案对比 + 技术约束 | 技术/数据/成本/运营可行性 + 依赖风险 | 每项有结论+依据+风险；写不出降级方案=不合格 |
| PRD | 11 | 方案选择 + 指标树 + 验证计划 | 背景+目标+用户故事+功能规格+非功能+指标+风险 | 开发拿到能开工，不需追问；每个功能可追到方案对比表 |
| 开发进度表 | 12 | PRD + 团队容量 | 拆成迭代+里程碑+依赖+风险缓冲 | 每迭代有交付物+验收标准 |
| 上线检查清单 | 13 | PRD + 监测计划 | 功能/性能/安全验收 + 回滚 + 灰度 | 回滚方案有触发条件+步骤+负责人 |

### D4 发布与验证（阶段 14-17）

| 产物 | 阶段 | 输入 | 生成指令 | 质量标准 |
|---|---|---|---|---|

### 全程

| 产物 | 时机 | 输入 | 生成指令 |
|---|---|---|---|

## HTML 是主界面

团队看 HTML，AI 读 Markdown。

- HTML 由 `product-lifecycle/scripts/stage_dashboard.py` 生成，单文件自包含，无外部依赖
- 页面内容 `contenteditable`，团队可直接改
- 点"导出 Markdown" → 改动写回 `artifacts/*.md`
- **冲突时以 Markdown 为准**（因为 AI 读的是它）

```bash
python3 ~/.codex/skills/product-lifecycle/scripts/stage_dashboard.py build <工作区> <阶段>
python3 ~/.codex/skills/product-lifecycle/scripts/stage_dashboard.py index <工作区>
python3 ~/.codex/skills/product-lifecycle/scripts/stage_dashboard.py all <工作区>
```

## 输出位置

```
<工作区>/
└── stages/
    └── NN-<阶段名>/
        └── artifacts/
            ├── <产物名>.md        ← AI 读这个（唯一真源）
            └── <产物名>.html      ← 团队看这个（可编辑）
```
